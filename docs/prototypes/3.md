# Prototype 3 — insert from the canvas

**Status:** step 1 shipped. Step 2 is the current charter. Write conclusions after step 2, then P4.

P2 made a scene a file. You still had to type `editPoint` to get a handle. P3 is UI-created **editors**, then **constructors that consume those editors**.

Visual language: [scenes.md](../scenes.md). Space commands today: same file.

## Editors vs constructors

| Kind | Examples | On screen | Writes |
| --- | --- | --- | --- |
| Editor | `editPoint`, `editDistanceToPoint` | filled dot, dashed ring | numeric literals |
| Constructor | `circle(c, r)`, `line(a, b)`, `group` | inert solid | no literals |

Step 1 inserts editors only. Unused editors are allowed. Step 2 inserts constructors that **name existing editors**. Do not snapshot a length from inert geometry. No wrapping an unmarked `3`.

## Step 1 (shipped)

**Space** opens a command palette on the focused pane. Commands come from the view host.

euclid2 and sdf2: **Point** and **Distance**. One `POST /__insert-editor` per completed command. Ghost while placing. Esc cancels.

- New scene: Space → Point → click. File contains `editPoint`. The handle drags and writes the literal.
- Space → Distance → click empty → click again. File contains `editPoint` + `editDistanceToPoint`. Dashed ring drags.
- Distance from a named point **in `scene()`** reuses the identifier.
- A handle declared in `plateLayout()` (outside `scene()`) is refused.
- Insert after evaluating the previous return so `plateLayout()` still runs first.
- euclid3 / sdf field: Space reports no insert commands. 2D widgets stay out of `mill.ts`.

`insertEditors` only writes **before the `return`**. First insert of a non-`__scene` return becomes:

```ts
  const __scene = <expr>;
  const p = editPoint(…);
  return __scene;
```

Later inserts add lines above `return __scene`. Replace from the **line start** of the return statement (indent stays two spaces).

Distance origin: `widgetInSceneFunction` + `widgetBindingName`. Inline `editPoint(0,0)` in the return has no name → refuse, ask for a new point.

### Learned

**Stale `scene()` after insert.** Peek saw a new `edit*` while runtime still had the old gizmos (`5 widgets … 6 edit* calls`). Empty `hot.accept(paths, () => {})` discarded Vite’s new module; `import()` of the glob URL without `?t=` returned the cached `scene()`. Fix: accept callback calls `applyHotScenes`; plugin `reloadModule` after insert. Re-`import()` of the bare glob URL is wrong. See [layout.md](../layout.md) (HMR).

**Gizmos > edit* calls** still means unrolled helpers. **edit* > gizmos** means the running module is stale.

**Indent.** Inserting at the `return` keyword left leading spaces on the first new line. Cut from line start.

**Layout widgets.** Inserting *before* `plateLayout()` would shift every mill/nest index. Keep evaluation order: layout helpers run, then new `scene()` editors.

## Step 2 (current) — constructors that consume editors

Palette verbs that **only consume editors**. First verb: **Circle**. Then **Line**, same rules.

euclid2 only for constructors (`circle` / `line` / `group` live in `@design-scenes/geom`). sdf2 keeps Point / Distance; do not emit `circle()` into a 2D SDF scene.

### Circle — click sequence

1. Space → **Circle**.
2. Click a point gizmo whose `editPoint` is a named `const` **in `scene()`**.
3. Click a distance gizmo whose first argument is that name (`editDistanceToPoint(p, …)`).

Ghost: a circle from the picked origin and the live radius (hover the ring, or drag out if a radius is already chosen). Esc cancels. One text edit on success.

### Circle — AST

Ensure `circle` (and `group` when needed) is imported from `@design-scenes/geom`.

Need two identifiers already in `scene()`, e.g. `p` and `d`. Insert **no new `edit*`**.

Return rewrite:

- `return <expr>;` where `<expr>` is not already `group(() => […])`:

```ts
  const __scene = <expr>;
  return group(() => [__scene, circle(p, d)]);
```

- `return __scene;` already:

```ts
  return group(() => [__scene, circle(p, d)]);
```

- `return group(() => [ … ]);` — append `circle(p, d)` as a last array element. Keep existing indent.

Stacked Circles must not create a second `__scene`. Prefer appending inside the existing `group(() => […])`.

`circle(p, d)` is inert geometry. The point and dashed ring stay; they still write `p` and `d`.

### Line — after Circle works

Space → **Line** → click two named `editPoint`s in `scene()` → `line(a, b)` appended the same way as Circle. Two clicks, order is `a` then `b`. Same origin twice is refuse.

### Pass

- Scene with `const c = editPoint(…); const r = editDistanceToPoint(c, …); return circle(c, r);`. Space → Circle → click `c` → click `r`’s ring. File gains `group(() => [__scene, circle(c, r)])` or an extra `circle(c, r)` in an existing group. A second circle appears. Widget count unchanged.
- New unused `p` + `d` from step 1, then Circle on those names. A circle appears; `p`/`d` still drag.
- Circle on a `plateLayout()` handle refuses (same status as Distance).
- Circle when the distance’s origin is a different point refuses.
- Line on two scene() points appends `line(a, b)`.
- euclid3 / sdf: still no constructor commands.
- `pnpm --filter @design-scenes/shell test` covers the AST cases (including stacked Circle and `__scene` already present).
- Insert still goes through `/__insert-editor` + `reloadModule` + `applyHotScenes`. Cameras stay.

### Fail (stop)

- Constructor invents new `edit*` or numeric literals for the circle.
- Snapshot a length from inert geometry into an expression.
- Prepending constructors (or editors) before `plateLayout()`.
- Putting `circle` in `demo/` or a library to make the palette work.
- sdf2 emitting `circle()` / `group()`.
- A toolbar of CAD buttons.
