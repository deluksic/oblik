# Prototype 3 — insert editors from the canvas

P2 made a scene a file. You still had to type `editPoint` to get a handle. P3 is UI-created **editors** (measurements).

Visual language and Space commands: [scenes.md](../scenes.md).

## Step 1 (shipped)

**Space** opens a command palette on the focused pane. Commands are registered by the **view**.

euclid2 and sdf2: **Point** and **Distance**. Insert into exported `scene()` via `POST /__insert-editor`. Ghost while placing. Esc cancels.

- New scene: Space → Point → click. File contains `editPoint`. The handle drags and writes the literal.
- Space → Distance → click empty → click again. File contains `editPoint` + `editDistanceToPoint`. Dashed ring drags.
- Distance from an existing named point in `scene()` reuses the identifier.
- A handle declared in `plateLayout()` (outside `scene()`) is refused.
- Insert after evaluating the previous return so `plateLayout()` still runs first.
- euclid3 / sdf field: Space reports no insert commands. 2D widgets stay out of `mill.ts`.

HMR after insert must apply Vite’s new module. Peek of the new file against a stale `scene()` looks like “N widgets, N+1 edit* calls.” See [layout.md](../layout.md) (HMR).

## Step 2 (next)

Palette verbs that **only consume editors**: `circle(c, r)` from an existing point + distance, rewriting `return` into a `group` when needed. Still no “pick a line as a value.”

## Out of scope

- Scene-specific `bolt` / `slot` registries
- Nested docking
- Click-to-wrap an unmarked literal (`wrap point` later)
