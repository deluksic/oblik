# Prototype 7 — profiles on the euclid2 tape

**Status:** design. Not a go-ahead to build. Capture the direction after the P6 style sheet failed, then cut **one** next slice: a profile primitive and a Profile tool in euclid2.

P6 stays the running runtime (`packages/oblik`, `apps/demo`). This charter is the memory; implementation starts only when we say go.

## Why

A project-wide style sheet keyed by uuid failed for three reasons that are the same reason:

- Paint was not colocated with anything a human reads.
- Copying or duplicating a scene did not take the look along (ids restamp; the sidecar does not).
- Helpers cannot be reused across views: one id is the right join for *editing a literal* and the wrong join for *how this scene paints*.

Colocating `{ style }` on `circle()` fixes copy-paste for a file that *is* the drawing and poisons reuse the moment a second system looks at the same code. Ignoring extra metadata at runtime does not help the reader: the call still accretes `{ style, mill, tex }`.

**Style is a view. Construction is a tape.** Euclid2 stays the sketch (literals, sliders, snap, insert, default draw, jump-to-source). Publication — fills, TeX, line weights, arrow caps, empty white paper — is a later scene type looking at that tape. Fusion-like solid / sheet-metal is another type looking at the same **curves and profiles**, not at paper swatches.

The missing object on the tape is not a color. It is a **profile**: a closed cycle of finite curves (segments and arcs), optional holes. Paper will fill it. Solid will extrude it. If P7 only invents a paper-local hatch, every later type reinvents the face.

## Horizon (not P7)

Remember this; do not build it in this prototype.

### Paper (name TBD)

A new `Scene` union member. Start from an euclid2 scene. Empty white page, onion skin **on**. The paper document is **ink**, not geometry. Nothing is on the page until you ink it — the opposite of euclid2’s default-draw.

**Consume the tape, not a return bag.** `build()` returning `{ A, B, drill }` is a second API. The sketch already exposes every constructor site (id, bind, kind, value). Join ink by **id**. Binds are default label text, not keys. Result drilling is how you get “the figure can only name what the scene remembered to export.”

**Onion skin is a lightbox.** Ghost the whole sketch (points *and* lines together). Filtering is **pick-only**, not visibility: a stroke applicator must not take a point click (fall through to the line); a point applicator still prefers the point. You need both ghosts to read the drawing.

**Applicator, not constructor.** Space opens a style palette (provided + user chips: color, width, dash, double/triple, point shape/outline, arrow **caps** on finite strokes). Click a compatible ghost → that id is inked with the current named swatch. Select on a ghost inks the default for that kind. Eyedropper / erase. No insert, no handles — moving `lamp` happens in the sketch; paper rides the same ids.

**Named swatches, not a uuid sidecar.** The paper file stores `id → swatch name` (and paper presets: white/cream, blank/dots/lines/grid). Changing `textbook.emphasis` restyles every use. Palettes are modules you can `import`. Inline override is the exception.

**Sync.** New sketch geometry appears as ghosts, not auto-ink. Deleted sites leave orphan ink rows you delete. No declaration-sync compiler in v1; warn like today’s kind mismatch.

**Proving publication.** Shelf as a blog figure: cellar dashed, shelf heavy, lamp hollow, live `d(L,P)` label, onion off, export SVG without host chrome. If that SVG still needs the dark construction UI to be understandable, the type is not done.

**Code that GUIs cannot keep honest.** The paper is a function of a live tape (drag the sketch, the embed moves). One sketch, many papers (loop, steps, print vs post) without copying paths. Labels from values so captions cannot rot. `occ` / binds / kinds are structure, not groups you hope held. Clicks *write* TypeScript (`ink("o_lamp", "textbook.point")`); they are not an opaque document.

Arrows are stroke **caps**, not extra objects. Infinite lines probably do not get caps (no finite end).

### Common language (curves → profiles → verbs)

Three layers so tools are not rewritten per purpose:

| Layer | Holds | Must not |
| --- | --- | --- |
| `geom/` | Points; infinite lines; **finite curves** (segment, arc-on-circle); **profiles** (outer cycle, optional hole cycles) | Pens, TeX, extrude depth, paper |
| Tape | Those values + id, bind, occ | View-specific bags |
| Scene types | Verbs on the same pick vocabulary: point, curve, profile | A private `Path` type each |

**Declared cycle, not live-paint magic.** Fusion auto-finds sketch faces; identity is slippery and Git sees arrangement. Start with an **explicit** profile (ordered curve refs, written by a tool into the sketch file). Arrangement that *proposes* a cycle you commit can come later.

Infinite lines are not edges until bounded. An arc is not a polyline of the circle. Endpoints are the sketch’s intersections, not coincident points each tool invents. Holes are inner cycles.

The **region / profile tool** is a shared authoring gesture (click curves that meet until the cycle closes). Paper’s last call is `fill`; solid’s is `extrude`. Same chain. P7 puts that gesture in **euclid2** so the artifact exists before a paper type needs it.

## P7 slice — profile in euclid2

**Do this, and only this, when we implement:** make a profile a geom value, a traced constructor, and a Space tool, visible on the euclid2 paper we already have.

### Inputs

The **tool** is **point, carrier, point, carrier, …** until the next point is the start. Vertices are existing points (binds, crossings, gliders). Each carrier click is a witness on a 1D thing through the current point — circle, segment, line, parallel — with an arrow **at the cursor** (curved vs straight). You never “take the whole segment” unless the next point happens to be its other end.

Hand-typed still names the **spans** the clicks produced:

```ts
const chord = segment(A, B, "o_ch");
const bow = arc(reach, A, B, 1, "o_bow");
const slice = profile(chord, bow, "o_slice");
```

Optional bind on the profile (Tab / name field).

**Not inputs:** holes, polylines of free clicks, style. Unbound strokes are **not addressable** in `Expr`. If a span is already a **named segment** whose ends are the two vertices, the profile refs it. Interior-to-end or line-walk inserts `segment(A, B)` (or `arc(c, A, B, k)`), not the unsplit original stroke.

Pick follows the phase: point slot prefers points; carrier slot prefers the stroke/circle and does not let a coincident point steal.

### Witness-first (every carrier)

**Circle** — two spans once both points exist. Witness on the ring is `k`. Hover arrow is winding from the current point through the cursor.

**Segment or line** — one span once both points exist (segment AB). The arrow is only **which way to leave** the current point. Interior (glider, crossing): two ways. Infinite / parallel: two rays; the next point must lie on the chosen ray. Endpoint of a named segment: one legal arrow, toward the other end — next point can be that end (ref the segment) or a point short of it (new `segment(A, B)`).

If the arrow is wrong, move before clicking. Tab flips `k` on an arc in the preview after both points exist.

Pass (chord + bow): click A, click the chord toward B, click B, click the circle (arrow shows the bow), click A to close. Interior: click lamp, click cellar with left/right arrow, click the next point on that line, …

### Data format

Geom (style-blind, NaN if any piece is NaN):

```ts
type Arc = { kind: "arc"; circle: Circle; a: Vec2; b: Vec2; k: 1 | -1 };
type Profile = { kind: "profile"; outer: Array<Segment | Arc> };
```

Disk matches other constructors: trailing id string, **variadic edges**, no JS array and no `{ style }`. `Expr` already prints `profile(chord, arc(reach, A, B, 1))` as nested `call`s. Do **not** add an array `Expr` kind for P7.

Traced **`arc` is a tape node** (own id, pickable span). `profile` refs those values. The circle remains the carrier; the arc is the finite span. Full 360° is not an arc; a hole that is a whole circle waits.

Outer cycle only. Close = first vertex equals last (within the construction, not a view epsilon). Winding: constructor stores click order; view can fill even-odd. Geom does not store color.

### Missing (in the tree today)

- `Arc` / `Profile` in `geom/`; finite-curve union; `isFiniteValue`; path tessellation for SVG (arc as `A` or cubic, **not** a polyline of the circle as the source of truth)
- `arc` / `profile` in `constructors` (`$site` dof `[]`); `constructors` map; analyze already follows `$site`
- Space: `ToolId` `"profile"`; verb module; **pick bias** so a stroke/circle click is not stolen by a point (same rule as paper’s applicator)
- Scope is bind-only (`scopeFromTrace` skips unnamed). Need named segments as first-class refs (carriers already include segments — use that)
- Face pick (`contains` for segment+arc loops); muted default fill in `Ink`; ghost of the in-progress chain; **direction arrow at the cursor** when hovering a carrier for a witness (curved on circles, straight on lines/segments)
- Hoist: nested `arc(…)` inside `profile` args, same as nested `lineIntersection`
- Walking an infinite line **inserts** `segment(A, B)` as the finite edge (that is the bounding rule, not a refuse-and-stop)
- Shelf as it stands **cannot** close a segment+arc face: `A` is the center of `reach`, not a point on it. The pass scene must put **two points on a circle** and a **named chord**

### Tool (when we build it)

Space → Profile. Docked preview is the call. Clicks: **point → carrier → point → carrier → …** until a point click is the start. Hover on a carrier shows the leave-A arrow at the cursor. Ghost: chain so far. Enter commits if `≥ 2` spans and the last point equals the first. Esc cancels. Insert into the euclid2/helper file.

### Pass / fail

**Pass scene:** a circular segment (chord + one arc), not Shelf unmodified. Two `pointOnCircle` (or two intersections with the same circle), `const chord = segment(A, B)`, `arc(c, A, B, k)`, `profile(chord, bow)`. Space-build of the same is also a pass.

**Pass:** disk shows `arc` + `profile` with binds; drag a point or radius and the fill follows; a miss NaNs the profile like other geom; stamp ids; pick the face; inspect origin is the `profile` site. A later scene type could extrude the same value.

**Fail:** approximating the arc as a point polyline; fill as CSS on the circle; sidecar; unnamed `segment(A, P)` duplicated as a second call to make a ref; auto-faces with no `profile(` on disk; “closed” only because the view clipped infinite lines.

## Not this prototype

- Paper / figure scene, onion skin, palettes, embed SVG, TeX labels, applicator
- Replacing or extending the P6 uuid style sheet (treat it as a failed experiment; do not grow it)
- Fusion / sheet-metal / extrude
- Computed arrangement, live-paint “click the well”
- `vector`, general `polyline`, fillets/slots as constructors (arcs-on-circles in a profile are the fillet-shaped *edge*, not a fillet kernel)
- Standalone decorative arrows; caps wait for paper stroke styles
- Forcing `build()` to return a public bag for join keys

## Open (when we implement)

- Euclid2 fill always-on vs a temporary proof paint until paper exists
- Whether a 2-edge profile (chord + arc) is enough for the tool’s first cut, or we require ≥ 3 (sector)

Already locked: traced `arc`; variadic `profile`; outer-only; no array `Expr`; tool is **point, carrier, point, carrier** until close; witness arrow at the cursor; span is A→B (ref named segment only when those are its ends); Tab on arc `k` as correction.

## Honesty

Do not rebuild Pathfinder, a second SVG scene type, or `{ style }` on constructors in order to “see a fill.” The fill in P7 is proof the **value** exists. The common language is the value.
