# Prototype 7 — profiles on the euclid2 tape

**Status:** building. Profile lives in euclid2 (`packages/oblik`, `apps/demo`). Horizon (paper scene, palettes, Fusion) is still not this prototype.

P6 stays the running runtime. This charter is the memory for what we cut and what we did not.

## Why

A project-wide style sheet keyed by uuid failed for three reasons that are the same reason:

- Paint was not colocated with anything a human reads.
- Copying or duplicating a scene did not take the look along (ids restamp; the sidecar does not).
- Helpers cannot be reused across views: one id is the right join for *editing a literal* and the wrong join for *how this scene paints*.

Colocating `{ style }` on `circle()` fixes copy-paste for a file that *is* the drawing and poisons reuse the moment a second system looks at the same code. Ignoring extra metadata at runtime does not help the reader: the call still accretes `{ style, mill, tex }`.

**Style is a view. Construction is a tape.** Euclid2 stays the sketch (literals, sliders, snap, insert, default draw, jump-to-source). Publication — fills, TeX, line weights, arrow caps, empty white paper — is a later scene type looking at that tape. Fusion-like solid / sheet-metal is another type looking at the same **curves and profiles**, not at paper swatches.

The missing object on the tape is not a color. It is a **profile**: a closed cycle of **spans** — each span is “from this point to that point along this existing carrier,” not a new segment or arc the profile invented. Paper will fill it. Solid will extrude it. If P7 only invents a paper-local hatch, every later type reinvents the face.

## Horizon (not P7)

Remember this; do not build it in this prototype.

### Paper (name TBD)

A new `Scene` union member. Start from an euclid2 scene. Empty white page, onion skin **on**. The paper document is **ink**, not geometry. Nothing is on the page until you ink it — the opposite of euclid2’s default-draw.

**Consume the tape, not a return bag.** `build()` returning `{ A, B, drill }` is a second API. The sketch already exposes every constructor site (id, bind, kind, value). Join ink by **id**. Binds are default label text, not keys. Result drilling is how you get “the figure can only name what the scene remembered to export.”

**Onion skin is a lightbox.** Ghost the whole sketch (points *and* lines together). Filtering is **pick-only**, not visibility: a stroke applicator must not take a point click (fall through to the line); a point applicator still prefers the point. You need both ghosts to read the drawing.

**Applicator, not constructor.** Space opens a style palette (provided + user chips: color, width, dash, double/triple, point shape/outline, arrow **caps** on finite strokes). Click a compatible ghost → that id is inked with the current named swatch. Select on a ghost inks the default for that kind. Eyedropper / erase. No insert, no handles — moving `lamp` happens in the sketch; paper rides the same ids.

**Named swatches, not a uuid sidecar.** The paper file stores `id → swatch name` (and paper presets: white/cream, blank/dots/lines/grid). Changing `textbook.emphasis` restyles every use. Palettes are modules you can `import`. Inline override is the exception.

**Sync.** New sketch geometry appears as ghosts, not auto-ink. Deleted sites leave orphan ink rows you delete. No declaration-sync compiler in v1; warn like today’s kind mismatch.

**Proving publication.** Shelf as a blog figure: cellar dashed, shelf heavy, lamp hollow, live `d(L,P)` label, onion off, export SVG without host chrome. If that SVG still needs the dark construction UI to be understandable, the type is not done.

**Code that GUIs cannot keep honest.** The paper is a function of a live tape (drag the sketch, the embed moves). One sketch, many papers (loop, steps, print vs post) without copying paths. Labels from values so captions cannot rot. `occ` / binds / kinds are structure, not groups you hope held. Clicks *write* TypeScript (`ink("o_lamp", "textbook.point")`); they are not an opaque document.

Arrows are stroke **caps**, not extra objects. Infinite lines probably do not get caps (no finite end).

### Common language (curves → profiles → verbs)

Three layers so tools are not rewritten per purpose:

| Layer | Holds | Must not |
| --- | --- | --- |
| `geom/` | Points; infinite lines; segments; circles; **spans** (a, b on an existing carrier); **profiles** (outer cycle of spans, optional hole cycles) | Pens, TeX, extrude depth, paper; extra segments/arcs whose only job is to feed a profile |
| Tape | Those values + id, bind, occ | View-specific bags |
| Scene types | Verbs on the same pick vocabulary: point, curve, profile | A private `Path` type each |

**Declared cycle, not live-paint magic.** Fusion auto-finds sketch faces; identity is slippery and Git sees arrangement. Start with an **explicit** profile (ordered curve refs, written by a tool into the sketch file). Arrangement that *proposes* a cycle you commit can come later.

Infinite lines are not edges until a span names two points on them. Walking a circle is a span on that circle (`k` chooses which way), not a polyline and not a new `arc(` on disk. Endpoints are the sketch’s points. Holes are inner cycles.

The **region / profile tool** is a shared authoring gesture (point, carrier, point, … until close). Paper’s last call is `fill`; solid’s is `extrude`. Same chain. P7 puts that gesture in **euclid2** so the artifact exists before a paper type needs it.

## P7 slice — profile in euclid2

**Done in this slice:** a profile geom value, unmarked `along`, a traced `profile` constructor, a Space tool, muted fill on the euclid2 paper.

### Inputs

The **tool** is **point, carrier, point, carrier, …** until the next point is the start. Vertices are named points or **crossings** (insert hoists `lineIntersection` / `circleLineIntersection` / `circleCircleIntersection`). Each carrier click is a witness on a 1D thing that already exists — circle, segment, line, parallel — with an arrow **at the cursor**.

The profile does **not** create geometry to name a carrier. Segments are treated as infinite supporting lines. Off the line: closest point, keep going.

Hand-typed:

```ts
const chord = segment(A, B, "o_ch");
profile([A, chord, B, along(c, 1)], "o_slice");
```

`along` is unmarked (like `dist`): no trailing id, not a tape node. Only `profile` is traced. Trailing id on **profile only**. The cycle is an **array**, then the optional id.

Walking cellar from the lamp: `profile([lamp, cellar, R, …], "o_face")` — no `segment(lamp, R)`.

**Not inputs:** holes, polylines of free clicks, style, a traced `arc` site. Unbound strokes are not addressable; free clicks in a point slot are ignored. Crossings are vertices.

Pick follows the phase: point slot prefers points; **the start point has a very fat snap when the cycle can close**; carrier slot prefers the stroke/circle and does not let a coincident point steal. Fill pick is last (behind points and strokes).

### Witness-first (every carrier)

**Circle** — always `along(c, k)`. Bare `c` is not a cycle item. Hover arrow is winding from the current point through the cursor. Tab flips `k` on the last circle.

**Segment or line** — bare ref, treated as infinite. The arrow is which way to leave the current point. Next point can be an end or short of it.

### Data format

```ts
type Along = { kind: "along"; carrier: Circle; k: 1 | -1 };
type Fillet = { kind: "fillet"; at: Vec2; r: number };
type Profile = {
  kind: "profile";
  outer: Array<{ a: Vec2; b: Vec2; carrier: LineLike | Circle; k?: 1 | -1 }>;
};
```

Disk: `profile([A, chord, B, along(c, k)], id?)`. Vertex slots accept `fillet(A, r)` (unmarked, like `along`). Geom stores projected vertices (closest point on the infinite line / circle). Close is implied (last carrier returns to the first point). `along` and `fillet` are not `$site`.

### Tool

Space → Profile. Clicks: **point → carrier → point → carrier → …** until a point click is the start. Insert **only** the `profile([...], id)` statement. Do not insert helper `segment`/`arc` lines.

### Pass / fail

**Pass scene:** `apps/demo/src/scenes/pie.ts` — three `pointOnCircle` on one reach, radii as segments, `roundOffset(profileValue([O, oa, A, along(reach, 1), B, ob]), -gap)`.

**Fillet (code-only):** `apps/demo/src/scenes/fillet.ts` — one `r` on every `fillet(·, r)`: opposite corners, all-round + inset, adjacent overlap (vanishes past ~0.7), L-notch, sector rim/tip, fillet at a 180° origin (left sharp), clockwise square. No Space tool.

**Pass:** disk shows the array cycle; drag a point or radius and the fill follows; a miss NaNs the profile; stamp the **profile** id only; pick the face (lowest precedence); inspect origin is the `profile` site.

**Fail:** extra `segment`/`arc` whose only purpose is to feed the profile; polyline of the circle as the source of truth; CSS fill on the circle; sidecar; auto-faces with no `profile(` on disk.

## Not this prototype

- Paper / figure scene, onion skin, palettes, embed SVG, TeX labels, applicator
- Replacing or extending the P6 uuid style sheet (treat it as a failed experiment; do not grow it)
- Fusion / sheet-metal / extrude
- Computed arrangement, live-paint “click the well”
- `vector`, general `polyline`, slots as constructors (arcs-on-circles in a profile are the fillet-shaped *edge*; `fillet(A, r)` is a vertex witness inside `profile([...])`, not a second face)
- A Space tool for fillet (code-only for now)
- Standalone decorative arrows; caps wait for paper stroke styles
- Standalone traced `arc` as its own tape node (a later Arc tool — P7 walks the circle via `along`)
- Forcing `build()` to return a public bag for join keys

## Open (later)

- A validator that warns when a named point is far from its carrier (constructor still projects)
- Holes; full-circle as an edge

Already locked: `profile([…], id)`; unmarked `along(c, k)` on every curve; unmarked `fillet(A, r)` in a vertex slot; bare line/segment as infinite; points always named; closest-point not a refuse; fill last in pick; close-point first when the cycle can close; no extra `segment`/`arc` from the tool; Tab flips circle `k`.

## Honesty

Do not rebuild Pathfinder, a second SVG scene type, or `{ style }` on constructors in order to “see a fill.” The fill in P7 is proof the **value** exists. The common language is the value.
