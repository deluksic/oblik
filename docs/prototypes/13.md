# Prototype 13 — tracing a raster reference: an `image(...)` trace node

**Status:** partly built. The charter comes from the [P12 postmortem](./12.md) — the convention recorded in [`intent.md`](../intent.md), "the next charter is written from the postmortem". Landed so far: the `image(...)` node itself (value, constructor, patch schema, `source/image-edit.ts`, the four pick arms) and the asset endpoint. Still open: the GPU layer, the import adapters, the inspector.

## Why

The sketch cannot hold the thing being traced. You measure a known distance, rotate, flip and position the reference in an external editor, then draw next to a picture that is not on the paper — and when the scene file moves, the reference does not come with it. `intent.md`'s horizon has an unrelated package consuming an exported artifact "even a PNG"; the useful half now is the inverse, a reference the scene **owns**.

## Locked (product)

**Storage is an asset file, not source.** The bitmap is written to `<appRoot>/public/assets/<slug>-<hash>.<ext>` and served by Vite at `/assets/…`; the scene source holds only the URL. No base64 in source, and no import line either — Vite's `publicDir` serves that directory at the root, so `image("/assets/gear-9f3a2c11.png", …)` just resolves.

**Any format the browser can decode; nothing else.** The acceptance test is `createImageBitmap(blob)` resolving. PNG, JPEG, WebP — whatever the browser decodes — is stored as given, so the extension follows the source rather than being forced to `.png`. A format the browser cannot decode is dropped **before** upload, with an error, and writes nothing.

**Three ways in.** Paste a screenshot from the clipboard, drop a file on the canvas, or pick one from the inspector. Pasting an image **URL** is deliberately out of scope: it would need the plugin to fetch the URL server-side to dodge CORS, which brings a size cap and an SSRF surface this prototype should not absorb. The three byte-paths share one pipeline.

**The image is a trace node like any other.** `image(...)` takes an `id`, has an occurrence, is selectable, editable in the source text, and patchable through an endpoint — the same contract as `point`, `region` or `slider`. It is a parallel `TraceValue` arm, not a `Geom` and not a `CsgOperand`: nothing composes it, it never enters a CSG tree, and it is not an operand.

**Original size.** Import gives the node the file's pixel dimensions, 1 bitmap pixel = 1 world unit. A retina screenshot is therefore twice as many world units as it looked on screen; that is a fact about the file, not a decision, and how large it _looks_ is the camera's business. Fitting it to the pane is a camera move, not a rect write.

**Pick priority is below regions** — an image is grabbed only when nothing else is in reach.

**The inspector is the transform UI**: rotate in 90° steps, flip, fade, numeric x/y/w/h and measure, plus drag-to-move on the canvas. There is no on-canvas transform tool and no bbox grips.

## The node

Props, all numeric so they stay patchable and serializable (`exprSchema` has no boolean literal):

```ts
image(src: string, x: number, y: number, w: number, h: number,
      rot: 0 | 90 | 180 | 270, flip: 0 | 1, fade: number): Image
```

- `x`/`y` is the **pre-rotation top-left**; `rot` turns about the rect's centre. `flip` mirrors about the vertical centre axis. `fade ∈ [0,1]` mixes the image toward the paper colour.
- An explicit world rect — not a scale factor over the intrinsic size — is the whole point: **eval never learns the bitmap's pixel dimensions**, so eval, pick and the GPU stay pure and device-free. Aspect ratio is preserved by the import flow (the client knows the bitmap size) and by uniform scale operations; independent `w`/`h` still allow deliberate distortion.
- `image` registers as a traced constructor with its `mark(...)` site spec, in the same constructors object as everything else, so insert / patch / mention / stamp keep working unchanged. Patch schema follows `paintPatchSchema`/`parsePaintPatch`; the edit function follows `source/paint-edit.ts`.
- Adding the `TraceValue` arm is the point of the exercise for the compiler: every exhaustive switch over the value/trace unions fails to build until it has an `image` case. Those cases are the feature's todo list.

**Pick arms** (`euclid2/pick.ts`), explicit in all four places rather than falling through the default rank:

| function        | image                                          |
| --------------- | ---------------------------------------------- |
| `isFiniteTrace` | true (a finite rect picks like any other fill) |
| `geomDistWorld` | distance to the rotated rect; inside → 0       |
| `aabbOf`        | the rotated rect's AABB                        |
| `pickRank`      | **4** — below `region`/`polygon` at 3          |

## Import

One pipeline, three adapters. All three converge on a `Blob` before anything is uploaded.

- **Paste.** A `paste` listener, not a keydown handler: a `KeyboardEvent` carries no clipboard data, and `navigator.clipboard.read()` is permission-gated. Iterate `clipboardData.items` and take `item.getAsFile()` — `clipboardData.files` is empty for a pasted bitmap in most browsers, and fills only when the clipboard holds real files (a PNG copied in Finder), which is the second case to support. Guards: skip when the target is an `HTMLInputElement`/`HTMLTextAreaElement` (the inspector's numeric fields must receive a pasted value), and skip when there is no image item and the clipboard has text. No location → the viewport centre.
- **Drop.** `dragover` + `drop` on the paper element, with `preventDefault()` on `dragover` — without it the browser navigates to the file and the scene is gone. The drop point, in world coordinates, is the image's centre.
- **Picker.** `<input type="file" accept="image/*">` behind an "Import PNG" affordance in the inspector.

**Validation happens client-side first**: decode, size cap, MIME → extension. A rejected drop must not leave an orphan in `public/assets/`.

**Naming is content-addressed.** The client sends a slug; the **server** sanitises it, hashes the bytes (`sha256`, first 8 hex) and writes `<slug>-<hash>.<ext>`. Identical bytes reuse the existing file, distinct images can never collide or overwrite, and the client cannot influence the path. The endpoint creates the directory (the demo has no `public/` yet), stays inside `resolveUnder`, and returns the served URL. Then the existing `/__oblik-insert` writes the node — two POSTs, so a failed insert leaves the asset on disk; that is accepted and surfaced, not silent.

The endpoint is a plugin change, so the dev server needs a **restart** before import can be exercised (the asset directory itself needs none).

## The GPU layer

An image is a textured quad drawn in the existing single pass, **immediately after `beginRenderPass` and before the grid**, so the reference sits under grid, fills, strokes and points. One pass — a second attachment would need `load` instead of `clear`.

- A cache keyed on `src` loads asynchronously: `createImageBitmap` → texture → sampled view with a linear, clamp-to-edge sampler. `createImageBitmap` is the _only_ format-specific code in the system, which is what makes "any decodable format" cheap. A 1×1 transparent placeholder covers unloaded and missing sources. Loading stays **outside eval**; textures are destroyed on unmount and a frame is requested when one becomes ready.
- The fragment does the theme-aware desaturation: `g = dot(rgb, vec3(0.2126, 0.7152, 0.0722))`, `rgb' = mix(mix(rgb, vec3(g), 0.85), paper, fade)`, alpha unchanged. `fade` is what lets sketch lines read on top of a photograph.
- **Paper comes from the existing theme path**, not a new uniform: `painter.setTheme(paper, gridColors)` already fires on a theme change, and the image layer joins that call. No `Frame` change, no `makeFrameValue` churn, and a theme switch re-renders with the new paper colour for free.
- The quad is the node's rect transformed by `rot`/`flip` — CPU-side, so the shader only samples.

## Inspector, drag, measure

- The inspector composes the existing sidebar pieces and writes every change through the patch endpoint.
- **Drag-to-move** is live, without a source write per frame: a pane-local override signal feeds the view through a memo (a shallow copy of the one node), and the release commits. The override reverts to source truth on a failed patch or a release outside the canvas.
- **Measure a known distance** is an inspector-armed mode, not a Tool — tools insert source, this only edits an existing node. Two canvas clicks (snapped to the top hit when one is near, a free world point otherwise) give `|AB|`; with `D` the known distance, `k = D / |AB|` and the rect scales about the anchor A: `x' = A + (x−A)·k`, same for `y`, `w' = w·k`, `h' = h·k`. The known distance is a numeric field in the inspector while the mode is armed; arming requires `D > 0`, and `|AB| < ε` refuses without writing.

## Pass / fail

**Pass.** Paste a screenshot with the canvas focused → a file appears under `apps/demo/public/assets/`, the URL loads, and the image draws under grid, fills, strokes and points. Paste with a numeric field focused edits the field instead. Paste text → nothing. Drop a file on the canvas → it lands at the pointer and the page does not navigate. Drop something the browser cannot decode → an error, and no file on disk. Rotate 90/180/270, flip, fade, numeric x/y/w/h edits, drag-to-move committing on release — all reflected in the scene source, and on reload the node comes back from source with its id. Toggle the theme → the desk and the faded image both move to the new paper colour. Arm measure, click two points over a known distance → the scale is applied about the anchor. Click over an image near a point or a region → the point or region wins; click bare image → the image is selected. Edit the node in the source file → the canvas updates.

**Fail would have been:** base64 in the scene source; a second renderer pass; an image node eval has to know the pixel size of; decode inside eval; on-canvas transform handles; a name the client chooses for a path; storing a format the browser cannot decode; pasting a URL through the page; an image that outranks a region in the pick order; a transform that writes the source once per pointer move.

## Not this prototype

- URL paste / any server-side fetch (a follow-up, with a size cap and its SSRF note).
- Cropping, opacity masks, multiple images per node, image re-import or re-linking.
- Non-uniform scale _tools_ (the fields allow it; nothing drives it as a gesture).
- Bitmap export or embedding the asset into an exported artifact.
- Image nodes in `figure/`, or anything that makes an image a `Geom`/CSG operand.
- Vectorising, autotracing, edge detection.
