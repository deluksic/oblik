# Prototype 6 — oblik: tape, draft, SVG

**Status:** open. Greenfield next to the P5 paper app (`packages/oblik`, `apps/demo`). Old `@design-scenes/*` stays until we migrate on purpose.

P5 proved the **look** (constructors on disk, handles from literals, Space as a command). P6 is the **runtime**: one package, Solid as the session, no hosts/plugins, no 3D/SDF in this cut.

## Why

The monorepo split (shell ↛ geom, hosts pushing inspect, three catalogs, `beginGeomFrame`, `withoutWidgets`, HMR swallow, `{ style }` on calls) was an accidental plugin platform. `session.ts` (~1600) and `insert-editor.ts` (~900) re-evaluate `scene()` in the TypeScript AST because the live graph was not the source of truth for tools.

## Locked

**Product.** Intent stays. TypeScript scene is the document. 2D only in this prototype. Scene types later via a **discriminated union**, not a host registry.

**Package.** Unscoped `oblik` (scope when we publish). `geom/` is a folder. Demo app `oblik-demo`. Scene type name: `"euclid2"`.

**Module.** `export default defineScene({ kind, title, camera?, build })`. No magic `export const title` / `export function scene`. Filename stem is the id.

**Eval vs view.**

```ts
evaluate(mod, { draft, annotations }): { value, trace }
```

- Constructors return values. Nested `evaluate` does not leak a tape. `emit` copies selected child nodes (same ids) onto the current tape.
- Default: every traced node is **visible**. Deviations are a sparse **sheet** keyed by uuid (not in this slice).
- `draft` is uncommitted literals (`Map<id, number[]>`), not a UI overlay. Solid memo: `evaluate(mod, { draft })`. rAF/SVG only paints.
- Scene type interprets `(kind, editable, value)` → stroke / gizmos / pick. Unknown kinds: skip.

**Identity.** Trailing call arg is **only** the id string: `circle(A, 2.5, "o_ab12")`. Ids are unique across the whole project (every user `src/**/*.ts` file). Stamp generates them; a second call with the same id is invalid — the host lists both sites and tells you to **delete the colliding trailing ids** so stamp can regenerate. A loop that hits **one** call expression (`occ`) is not a duplicate. Plugin stamps missing ids onto **user app source** (`apps/demo/src/**/*.ts`, not only catalog scenes). `editable` / `bind` / position live in a **virtual annotations** bundle merged across those files. Join key is the uuid, never `file:line:column`. Helpers called from `build()` join the tape because `current` is set and they have ids — there is no module filter in `traced()`. No id → no node.

**Helpers.** A layout module (`src/layout/mounting-plate.ts`) is not a scene. Catalog is `defineScene` files in `sceneDir`. Stamp/analyze/patch/HMR follow the helper; write-back uses `anno.file`. Nested `evaluate` still does not leak tape (`emit` copies nodes).

**`$site` on the function.** `circle[$site] = { dof: [1] }`. Plugin imports constructors; no parallel name table. Euclid2 **pixels** stay next to SVG components, keyed by `value.kind`.

**Context.** One `current` eval ctx; save/restore in `finally` (not a stack array).

**HMR.** Always apply the new module. Keep `draft` until that module’s `build()` has run and produced a trace, then drop the override. Do not compare literals to disk. Annotations HMR does not drop draft. Camera is a signal. No self-write swallow.

**Insert.** Fourth source job: `{ file, from, bind?, args: Expr[] }`. Palette (euclid2) `Expr`: `num` | `ref` | `call` | `member` | `neg`. Space: Point, Circle, Line, Segment, Parallel, Perpendicular, Slider. Snap reads the live tape. Each verb module owns click / ghost / preview / Tab fields / Enter; `tools/index.ts` only dispatches. Pane must not switch on `verb`. There is no `session.ts`.

**Gliders.** `pointOnLine` / `pointOnSegment` / `pointOnCircle` exist and are **Point-tool only**. Other tools consume existing gliders (as points) but must not *invent* one from a stroke click. Parallel lines can host a glider; they are not a special non-carrier.

**Length reuse.** Circle radius and parallel distance accept a typed literal, a slider name, or a field (`reach.radius`, `-shelf.distance`). A named point or crossing in that slot wins and writes `dist` / `signedDist` instead.

**SVG.** Euclid2 is Solid + SVG. Camera is a **group transform** over aspect-correct NDC `viewBox`, not world units in `viewBox`. Y-up via `scale(1,-1)`. Handles use **relative** pointer Δ (no jump-to-cursor). Canvas is a later swap if the tape is too large.

**Traces.** `segment(a,b)` is **one** node. End caps are euclid2 drawing. User `point()` is its own node. `geom/` never calls traced constructors (`constructDepth` is not the model).

**Stack.** Keep `Error.stack` for caller frames. Leaf site from the annotation map (disk). `/__map-stack` stays for callers against Vite’s transform.

**Not this slice.** Layout-as-kind, `emit` filters, named palettes, style sheet UI, paper 3D/SDF, `vector` / `polyline` / `arc`, gizmos on a bare `3` inside library math.

## Honesty (what we refuse to rebuild)

- AST mini-interpreter of `build()` for snap (`evalDerivedScenePoints`). Snap reads the live tape.
- Dual geom/gizmo frames and `withoutWidgets` publish maps.
- Inspect pushed from a canvas rAF through snapshot keys.
- `{ style }` / `__annotations__` on the constructor.

**Still inherent:** stamp AST, patch by id, HMR module swap, loop `occ`, NDC camera, `Expr` printing (euclid2, later).

## First slice (pass / fail)

Hand-typed shelf-like scene in `apps/demo`:

- `point` / `line` / `circle` / `segment` with trailing ids
- SVG shows strokes; editable point + radius handles
- Drag is relative; release patches literals; draft holds until the new module’s `build()` has run
- Space inserts Point / Circle / Line / Segment via `Expr` (snap from the tape)
- Missing id: plugin stamps the file

**Fail:** handles jump to the cursor; `segment` emits endpoint traces; draft cleared on annotations HMR while the old module is still live; `file:line:column` as the write key.

## Learned from using it

These only showed up by clicking, Tabbing, dragging, and watching HMR — not from the charter.

**The docked preview is still the command.** Tab cycles slots; typing goes into the focused field; Enter commits; Esc cancels. The caret lives in the preview source line, not a second HUD input. Point focuses the geometry args first and types a bind at the caret. Space on an empty search closes the picker. One overlay is cramped (Line still has no typed endpoints the way Point has x/y) but splitting fields into real inputs would fork the “preview is the call.”

**Ghosts are HUD, not world ink.** Infinite line ghosts and non-scaling strokes have to paint in the HUD SVG or they vanish under camera scale. If `hit()` throws (we passed a whole session into a length helper and `.trim()`’d `undefined`), the Point ghost simply stops updating — the tool looks dead, not crashed.

**Gliders vs field reuse is a tool policy, not a geom fact.** First reaction to “parallel + `pointOnLine` fights `.distance`” was to ban gliders on parallel lines and stop snapping them as carriers. That was wrong: a lamp on the cellar is a real construction. The rule that survives play: **only Point creates gliders**. Circle / Parallel / Line treat a stroke click as “use this geometry,” and a glider snap as a free point. When the length slot is open, a **pinned point or crossing wins over field reuse** — clicking `P` writes `dist(center, P)`, not `reach.radius` just because the pointer was near the ring.

**Pick order is the product.** Points always sort ahead of ink. No cycle-among-hits: top hit only, or you cannot tell what a click did. Hover must not steal the selected stroke’s look. Grab cursor comes from the same hover as the highlight. Editable circles are paths (not `<circle>`) so CSS stroke-width is in pixels, and you drag radius from anywhere on the ring.

**Click selects; drag does not.** Pointer-up with no move picks. A move only commits the literal. Re-picking the gizmo on drag-end *looks* like it “keeps selection” but it actually **selects after a move**, which is the wrong gesture. Keeping a *prior* pick across a drag is a reactivity problem, not a pick problem.

**Solid 2: the pane memo owns identity.** `createMemo` that returns `<Euclid2Pane …>` remounts the pane if it re-runs — camera, draft, and selection die. Branch on a **`sceneKind` memo** (`scene().kind`, a stable string). Put `scene={scene()}` only in JSX so it compiles to a getter; HMR then updates the live instance. Reading `scene().kind` *inside* that memo tracks the module object and remounts on every patch.

Do not “fix” HMR by copying an async memo into a signal from an effect. Effects are not for syncing state. `<Loading>` does **not** remount just because the async scene memo re-ran; it only falls back when that memo has no value yet. Scene-driven resets use function-form signals: `selectedKey` keys off `props.file` (same scene, new module → keep the pick); `draft` keys off `props.scene` (new module owns the literals → drop overrides).

**New scene files do not register themselves.** `import.meta.glob` is whatever the last transform of `scene-loaders.ts` saw. If the plugin appends an HMR tail and then *skips* re-transform, adding `shelf.ts` never appears in the picker until restart. The plugin must emit the loader map from a disk scan on every transform. That emit is **runtime JS** — `satisfies` / `import type` survive poorly (Vite strips the type import and leaves `satisfies`, which is a SyntaxError at `scene-loaders.ts:1`).

**Helpers join the tape through ids, not a module check.** `traced()` only skips when there is no eval ctx or no trailing id. A layout function called from `build()` is on the same `current`. We skipped helpers because stamp/analyze were `sceneDir`-only, so calls never got ids, and `module: ctx.module` then patched the scene file even if annotations knew the helper. Stamp user app source, merge the annotations bundle, prefer `anno.file` for write-back.

**Shared ids are a project error, not a namespace miss.** The annotations map is keyed only by uuid. `o_c2` on the plate helper and `o_c2` on the truss meant last-file-wins: inspect of plate `c2` showed `mountingPlateLayout` **in** `src/scenes/truss.ts`. Do not scope the merge per scene — stamp already makes unique ids. The host warns, lists every site, and says to **delete the colliding trailing ids** so stamp regenerates. A `for` loop that reuses one call (`o_ring`, `o_tick`) is `occ`, not a collision.

**Source maps have to chain, and peek cannot use basename.** Returning `{ map: null }` from stamp told Vite to drop the map. Browser stacks then sat on generated columns, and `/__peek` resolved `src/layout/mounting-plate.ts` by **basename** into `scenes/mounting-plate.ts`. Identity stamp now skips the transform (`return null` so Vite keeps the chain). Inserts return MagicString’s map with the **Vite** source name (`src/layout/…`, not `apps/demo/src/layout/…`). Capture uses V8 CallSites (generated positions — maps apply only when stringify-ing) and `/__map-stack` remaps them through `transformRequest`. Peek resolves under the app root; basename fallback is only a bare `shelf.ts`. Origin labels keep `src/layout/…` vs `src/scenes/…`.

**No `onHelperHot`.** P5 accepted helper modules on the loaders file, which **stops** HMR from bubbling to the scene, then poked `notifyHelperHot()` so frames would re-run. P6 scenes **import** the helper. A helper save invalidates the scene; `applyHotScenes` gets the new module; live ESM bindings are enough. Accepting helpers would recreate the extra channel.

**P5 2D scenes that fit the tape migrated.** Shelf (`-shelf.distance`, lamp glider, `dist` beam), shared-loop (`occ` + `signedDist`), truss (gliders + shared `.radius`), mounting-plate (layout helper + AABB inset + holes). Still missing vs P5 2D: `vector`, `polyline`/`arc`, fillets/slots, slider labels, style/fill.
