# Prototype 10 — user composite functions as Space tools

**Status:** building. Functions are inert; registering one with `defineTool` makes it appear in the Space palette like a built-in verb. Registering is explicit and collocated with the function; built-in tools stay imperative and untouched. The charter cut is composite-only (users cannot build new primitive constructors) and insert-only (no post-hoc editing of a placed call).

## Interaction (this cut)

`apps/demo/src/layout/tools.ts` registers five practice tools (Rect, Bolt circle, Ring, Keyhole, Bisect) that are imported from `main.tsx`, so they list for every scene. `?scene=tool-lab` is a blank board to try them.

Picking a registered tool opens a generic session: one Tab stop per argument plus a name, in param order.

| arg kind            | click empty space             | click pinned point     | click existing length                       | type                     |
| ------------------- | ----------------------------- | ---------------------- | ------------------------------------------- | ------------------------ |
| `point`             | new literal point             | mention it             | —                                           | name it                  |
| `region`            | —                             | click a face           | —                                           | name it                  |
| `segment`           | —                             | —                      | click a segment                             | name it                  |
| `length` + anchor   | numeric `dist(anchor, click)` | live `dist(anchor, p)` | reuse (`c1.radius`, `par.distance`, slider) | number / member / slider |
| `length`, no anchor | —                             | —                      | reuse                                       | number / member / slider |
| `number`            | —                             | —                      | reuse as a numeric literal                  | value                    |

**Args without a `def` are required.** The ghost and the insert wait until every required arg is populated — typed, clicked, or measured. Nothing renders before the first real fill (no shape parked at the cursor from defaults), and the ghost never shows a defaulted radius/width the user has not entered. Anchors let a required length **draft from the cursor** after its anchor is placed: click Bolt circle's center, move the mouse and the hole ring previews at the measured radius. A `def` (like Bolt's count, `n = 6`) pre-fills so a call can commit without typing that arg, and a click on a focused anchored length or an existing length overrides a default. The ghost is a **draft evaluation of the tool fn** — a throwaway `withEval` run whose trace renders muted in the view, re-ids per draft so a second placement of the same tool still previews.

Insert writes one stamped-less call into the focused function: `const bc = boltCircle(p1, dist(p1, p2), 6)` with the module import added relative to the dest file. Literal points are hoisted (`p1 = point(...)`) by the existing insert machinery. Bag members (`bc.holes`, `kh.face`) stay mentionable through the same helper-call analysis as `plate.face`.

## Locked

**`defineTool(fn, def)`** returns `fn` unchanged; `def = { title, prefix, args, hint?, name? }`. Name defaults to `fn.name`, must match the exported binding, and is the tool's palette id / session verb / callee written into source; it cannot collide with a built-in id. Re-registration overwrites (HMR-safe); duplicate names from a different module warn and last-wins. `prefix` drives auto binds (`bc`, then `bc2`, …) that never shadow the tool name.

**`arg.*` vocabulary**: `point`, `region`, `segment`, `length({ def?, anchor? })`, `number({ def?, integer? })`. Positional, matching fn params. `length` args are **expressions** (a live member/slider/`dist` stays linked); `number` args are **numeric literals**. `anchor` refers to an earlier point/region arg by label and is what enables click-to-measure and cursor-draft ghosts. Absent a `def`, an arg is required: ghost and insert wait until it is populated. `integer` is advisory in this cut.

**Registry is runtime and import-graph-visible**: a module registers when it is evaluated (imported by a scene or by the demo entry); nothing lists from un-imported files. The module URL is captured from the calling frame (`eval/stack`), mapped server-side to a relative specifier for the insert.

**Ghosts are traced, not drawn**: `ghost` returns `{ kind: "trace", nodes }`; the view renders those TraceNodes muted in a pointer-transparent band behind the real chrome, with per-draft namespaced keys so ghost copies never collide with live ids (or with each other). No per-tool render code.

## Pass / fail

**Pass scene.** `?scene=tool-lab`. Space lists the five registered tools alongside the built-ins; a search by title/hint finds them. `bolt circle`: click a center (empty space hoists a point), hover shows the hole ring at the measured radius, click to measure → the scene gains `const bc = boltCircle(p1, dist(p1, p2), 6)` (or a typed radius — nothing appears before the center click or an empty radius), the relative import appears when missing, and no trailing id is stamped onto the call. After HMR the geometry is traced, `bc.holes` is mentionable, and a hoisted `p1` handle drags. `rect`: click a corner, Tab and type width/height, the ghost appears only when both are populated. `bisect`: hover highlights the segment, click it → `const bi = bisect(S)`. `keyhole`: hover highlights the face, click fills it, click places the hole center, radius measures from it, the ghost shows the cut face. Built-in verbs are unchanged (their inserts still carry site ids and import from `oblik`).

**Fail:** user-created primitive constructors; editing or re-running a placed tool call; trailing site ids on tool calls; destructuring a returned bag; tools discovered statically from files nobody imports; a declarative rewrite of the built-in `point` / `slider` / `region` / `fillet` verbs; ghost draft-eval in the figure pane.

## Performance

Two costs showed up while dogfooding, both fixed at the source. Trace reuse deep-compares draw values, and glider values used to nest their whole ancestor tree, so a comparison walked 2^depth nodes — constructors now copy point args and values stay flat. A single scene edit also re-ran the world memo once per HMR event; the HMR writes are now coalesced into one macrotask and the scene cache answers synchronously, so one edit flushes the world exactly once.

## Not this prototype

- Two-click `arg.measure` (click a, click b → `dist(a,b)`) for dimension-style args
- Editing a placed call in place (no site-id machinery on tool calls) and any slider-created tool internals
- Carrier anchors (perpendicular offset from a line) and `integer` enforcement
- Caching/throttling of the per-pointer-move draft eval
- Ghost dots for point-kind nodes inside a tool's trace
