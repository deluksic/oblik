# Prototype 8 — mentionable scopes

**Status:** design. Do not implement until the locked decisions below survive review. Paper / publication stays paused (P7 horizon). This prototype is the missing editing object: **the JS environment you are constructing into**, not a group and not a return bag for paper.

P7 stays the running geometry. This charter is the memory for what insert, snap, and helpers actually are, and which refactors they force.

## Why

Helpers already join the tape. `mountingPlateLayout()` is one constructor site per call, many `occ`, ids stamped in `src/layout/mounting-plate.ts`. Inspect, drag, and fillet-by-id already follow **id**, including into a helper.

Insert and snap do not. They still pretend the scene is one `build()` with unique `const` names:

- `insertCall` only finds `defineScene({ build() { … } })` and only accepts names from that body plus file imports (`namesInBuildScope`). A ref that exists only in a helper throws `geometry constructed in a helper cannot be inserted yet.`
- The pane always POSTs `file: props.file` (the scene), even when the live node’s `module` is the helper.
- `scopeFromTrace` / `boundOf` / `snapBoundPoint` key named geometry by **`n.bind` where `occ === 0`**. Two helpers that both `const left` shadow. Two `plate()` calls look like a loop: only occurrence 0 is mentionable.
- `Expr.member` is only `{ object: string; field: "radius" | "distance" }` — length reuse, not `plate.hBottom`.
- Place / crossings store **bind strings**, then `exprOfPlace` turns them into `{ kind: "ref", name: bind }`. That print is only legal when the focused function has that identifier.

The product gap is **mentionability**: which names is it legal to print *here*, and which file/function is *here*. Reuse without that is a gallery of private geometry the parent cannot name.

## Locked (product)

**Scope is an editing object.** It is the insert destination, the mentionable set, and an invocation filter. It is not a group, not a transform, not a paper join, not `evaluate().value`.

**Three channels — do not mix**

| Channel | Role |
| --- | --- |
| Tape | See, drag, inspect, later ink. Helpers with ids join `current`. Join key is **id**. |
| Lexical names | Insert prints TypeScript. Refs must be in **that function’s JS environment**. |
| Helper return | What the **caller** may name (`plate.hBottom`, or `hBottom` after destructure). |

Scene `build()` should return void for publication later; do not block this slice on deleting demo `return { A }`. Constructors still return values. Helpers may return a small struct — that is the construction API, not a scene export map.

**Default focus:** the scene’s `build()`, its one invocation.

**Dive:** the function that owns the constructor site **and** the invocation you clicked. Breadcrumb like a stack: `build() · mountingPlateLayout · 1`. Editing occurrence N still rewrites the **shared definition**.

**Lock:** starting a constructing tool on a mentionable point locks that scope. Escape / empty unlocks the tool and returns focus to `build()`. Select-without-tool does **not** dive.

**Mute:** not snap-eligible, still drawn weak (onion-weak). Drag, inspect, and jump-to-source stay **global (id)**. Fillet / literal / slider patch-by-id stay unscoped.

**New `const`:** written in the focused function body, in that file. Preview prints **this scope’s** names (`hBottom` vs `plate.hBottom`).

**Expose** does both sides: field on the helper `return { … }`, and a caller binding if the parent discarded the value (`return mountingPlateLayout()` → `const plate = mountingPlateLayout()`). Do not mint a second id.

**Out of this slice:** auto-adding helper parameters; `group()`; paper; nested destructure / spread / ternary returns; typed bags; treating `occ` as another component; switch-scope-and-restart on a muted click.

## Pass / fail

Pass scene: mounting plate, parent binds the helper.

```ts
build() {
  const plate = mountingPlateLayout();
}
```

From `build()`: snap `plate.drill`, not private `hLeft`. Expose `hBottom` → `plate.hBottom`. Dive → insert a segment in `layout/mounting-plate.ts` before that function’s `return`. Two `plate()` calls: cannot finish a **dived** line from invocation A to B. From `build()`, `segment(a.c0, b.c0)` is legal — both are mentionable exports.

Fail: insert still landing in the scene when focus is the helper; printing `hLeft` from `build()`; using `occ` as the helper-call identity; a `group()` around `plate()`; adding a `ground` parameter to the helper so a private can meet a scene line.

## Focus and invocation

### Function identity

Identify the focused function by **source span**, not by tape bind.

- Default: `defineScene`’s `build` method / function (same finder as `findBuildBody` today).
- Dive: the innermost user function whose body contains the constructor (`anno.file` + line, already on the node). Named `export function mountingPlateLayout` is the happy path. `const layout = () => { … }` is the same span with a weaker `name`.

Stack function names are a label for the breadcrumb, not the key. V8 often omits names on arrows; `SKIP_NAME` already drops `anonymous`.

After HMR / insert, **do not** keep raw `{ line, column }` as the function key — spans move. Key the function as `{ file, name, role: "build" | "function" }`. Re-resolve the span from the current AST each time.

### Invocation ≠ `occ`

`occ` is per **id**, incremented in `traced()`. A loop **inside** a helper (`o_ring`) produces many occ in **one** invocation. Two `plate()` calls give every helper id occ 0 then 1.

**Do not use a single occ as “which plate().”** Invocation is the **caller stack frame** of the focused function: the user frame that *called* it, copied from a live node’s `stack`.

A constructor inside `mountingPlateLayout` typically has:

1. Leaf: constructor site in the helper (annotation pins this; `pinConstructorSite` overwrites frame 0).
2. Next: `build` at the `mountingPlateLayout()` call.

Filter: the node’s stack contains that caller frame (same canonical file + rank — see hard problem 1). Nodes from the other `plate()` do not.

Inside the focused invocation, named snap may still keep today’s **loop rule**: `occ === 0` among nodes that match the invocation. Sharpening “insert into the loop body vs before the loop” is later. v1 inserts before `return` in the focused function, as `insertCall` does in `build()` now.

### Cross-invocation

When **dived** into invocation A, B is muted even if it is the same id. You are editing the shared source with A’s live values; B is a second evaluation of that source, not a second component.

When focus is **`build()`**, both calls’ **returned** fields are mentionable (`a.drill`, `b.drill`). Connecting them is ordinary parent TypeScript. The “cannot finish a line from A to B” rule is for the dived helper, not for the parent.

## Mentionable set

Mentionable = the JS environment of the focused function:

- Locals (`const`, destructure names).
- Parameters.
- Imports (file-level).
- Closures from **outer functions in the same file** (nested helper inside the scene file can name `ground` from `build()`).
- **Not** names from an imported module’s caller. `mountingPlateLayout` in another file does not close over `build()`.

Plus, at the **caller**, fields of a helper result that this function bound:

| Caller writes | Mentions |
| --- | --- |
| `const plate = mountingPlateLayout()` | `plate.origin`, `plate.drill`, … |
| `const { drill, origin } = mountingPlateLayout()` | `drill`, `origin` |
| `const { drill: d } = mountingPlateLayout()` | `d` |
| `mountingPlateLayout()` / `return mountingPlateLayout()` | nothing until expose inserts a binding |
| `const face = plate()` when `plate` does `return drill` | `face` as that one geom |

v1 analysis of the **return** (helper file):

- `return { origin, drill }` — shorthand field → that binding’s id.
- `return { extra: hBottom }` — field → `hBottom`’s id.
- `return { extra: parallelLine(..., "o_in") }` — field → trailing id of that call (no bind).
- `return drill` — whole-value; caller names the geom, not fields.

v1 **out:** spread, ternary, `return helper()`, deep destructure, `const x = plate; x.drill`, reassignment. Inline object returns must be **identifiers or constructor calls**, not clones (clones drop `$node`).

Shortest mention wins when both exist (`hBottom` over `plate.hBottom`).

Product fields stay a **second** member step on a geom, not on the bag: `plate.drill.radius`, `hBottom.distance`. That is length reuse, already in the prompt as `reach.radius`.

## Expose

Command on a selected node that is **not** mentionable in the parent of its constructor function (inspect stays global, so this is available without dive).

Rewrite:

1. Helper: add `{ bind }` (or `{ field: bind }`) to an object-literal `return`. If there is no return, add `return { bind }`. If return is already `{ … }`, add the property. **If return is a single geom / non-object, refuse** — wrapping would break `const face = plate()`. Do not invent a second id.
2. Caller at the invocation frame: if the call is already `const plate = helper()` (or a destructure), stop after (1) — parent can now write `plate.hBottom`. If the call is discarded (`return helper()` or `helper();`), insert `const plate = helper()` (bind from `takeBind` on the callee name, e.g. `plate` / `mountingPlateLayout` → `mountingPlateLayout` prefix rules as today). If the caller destructures, add `hBottom` to the pattern.

One level only. Bubbling `hBottom` from helper → fixture → `build` is expose twice.

## Mute, lock, dive (UI)

**Without a tool:** click inspects (any invocation). Handles drag. Origin sidebar shows the stack. Breadcrumb / “Edit here” on the function header **dives**. Clicking the drawing does not implicit-dive.

**With a constructing tool, focus already set:** snap only mentionable geometry in that invocation. First mentionable click **locks**. A muted click **refuses** (does not complete the verb, does not dive). v1 pick is refuse, not switch-scope-and-restart — mid-verb dive is a surprise and a second implementation of lock.

**Escape:** clear the tool; if a non-`build` focus was locked for that tool, also return to `build()`. A dived focus with no tool stays until the breadcrumb / Escape on empty.

**Chrome:** scope mute is **not** Fillet chrome. Fillet sets `muteStrokes` / `mutePoints` / `hideSnap` and hides handles. Scope mute dims ink that is not snap-eligible but **must leave handles**. Do not reuse `mutePoints` for this. View already has a second mute path (`eligibleCarriers` for Profile). Add `mutedForScope(node)` beside it.

**Typed fields** (`centerRef`, `carrierRef`, …) parse the mention as printed (`plate.drill`, `hBottom`), not the tape bind.

## Hard problems

These are the reasons not to “just pass a file into `insertCall`.”

### 1. Stack coordinates are not source coordinates

`captureUserStack` records **generated** positions (V8 CallSites). Inspect remaps later via `/__map-stack`. Tools today never look at `stack` for snap; they use `occ` + `bind`. Invocation matching cannot wait on that async remap, and must not mix annotation lines (user source, pinned onto frame 0) with raw caller frames.

**Resolution:** do not parse source to find the invocation. **Copy the caller frame from the clicked node’s `stack`** (same coordinate system as every other node from that eval). Canonicalize paths (`normalizeStackFile` / a real join, not `normalizeSceneRelPath` which only rewrites using the *constructor* module — helper vs scene frames already disagree in `stackForNode` tests). Persist focus as `{ fn, invRank }` where `invRank` is the index of that caller frame among distinct caller frames of `fn` in this trace. Recompute after HMR. `pinConstructorSite` must not be used as the invocation key (it overwrites frame 0).

Arrow/`const layout = () => {}` with no `name`: rank still works; breadcrumb falls back to file stem.

### 2. Tape bind is not unique and `occ === 0` is the wrong filter

`scopeFromTrace` is already wrong for two `const left` in two functions. Place crossings (`a: string`, `b: string`), `PlaceHit.carrier.bind`, `hoverBind`, Profile `trace.find(n.bind === e.name && n.occ === 0)`, length hover, `eligibleCarriers` keyed by bind — all of it.

**Resolution:** snap and scope key by **id** (plus invocation). `PlacePoint` / crossings store ids, not binds. `exprOfPlace(p, scope)` asks the focused scope for the mentionable `Expr`. If a node is not mentionable, it must not have snapped.

Do not stuff `plate.hBottom` into `{ kind: "ref", name: "plate.hBottom" }`. `exprRefs` / `namesInBuildScope` treat that as one identifier and the insert validator will throw. That forces problem 3.

### 3. `Expr.member` cannot express helper fields

Today:

```ts
{ kind: "member"; object: string; field: ProductField }  // ProductField = "radius" | "distance"
```

Wired through `printExpr`, `exprRefs`, `hoistIntersections` (members are opaque), `evalLengthExpr` / `parseMember` (`lastIndexOf(".")`), insert **valibot** schema, and length tests (`reach.radius`).

Need `plate.hBottom` and `plate.drill.radius`.

**Resolution:**

```ts
{ kind: "member"; object: Expr; field: string }
```

- `reach.radius` → `member(ref("reach"), "radius")`
- `plate.hBottom` → `member(ref("plate"), "hBottom")`
- `plate.drill.radius` → `member(member(ref("plate"), "drill"), "radius")`

`field` is no longer a closed enum. Product vs bag is a **lookup**: if the object resolves to a circle / parallel, `radius` / `distance` are length; if it resolves to a helper binding, the field is a returned geom. `parseLengthTyped` already takes the last dot — `plate.drill.radius` splits into object `plate.drill` + field `radius` if we look up mentions by printed path **or** parse left-to-right against the mention graph.

Schema, `exprRefs` (root identifiers only), `printExpr`, `sameRef` (must compare Expr, not bind strings), `memberExpr` in `length.ts` — all change together. This is the first code refactor, not a tool-by-tool patch.

### 4. Insert destination is hard-wired to `build()` in the scene file

`findBuildBody` + `namesInBuildScope` + `usedIdentifiers(entire file)` + pane `file: props.file`. Fillet `patchVertex` is the exception: it searches the POSTed file by profile id (and tests already patch a helper in the **same** file). A helper in another file is never POSTed.

**Resolution:** `Insert.file` is the focused function’s file. `insertCall` takes a destination: that function’s body, insert before **its** `return` (or before close). `used` / `takeBind` from **that function** plus file-level imports — not every identifier in the file. Two functions in one file may both `const s`. File-wide `usedIdentifiers` would mint `s2` in the helper because `build()` already said `s`, and would block `hBottom` in `build()` because the helper used it. `ensureNamedImport` stays file-level.

Fillet patch stays unscoped (whole-file-by-id, including the helper path via `anno.file` / focused file). Constructor insert is scoped.

`namesInBuildScope` generalizes to `namesInFunctionScope(source, fn)`: imports + outer same-file functions + this body + params. Semantic check: each `exprRefs` root is in that set; each `member` chain is a returned field (or product field on a geom mention), not merely “`plate` exists.”

### 5. Mention graph is new analysis

`bindName` only sees `const ident = ctor(...)`. No bind for `return { x: parallelLine(...) }` or for the caller’s `plate.x`.

Need AST in **both** files, HMR’d like annotations (sibling virtual module, or extra fields on the bundle):

- Per function: return shape (bag fields → id, or whole-value id).
- Per call of a known helper: binding kind (const object, destructure map, discarded).

Join at the pane with the live trace: invocation rank selects which occ of those ids is the live geom. Do **not** read `evaluate().value`. Return the live branded geom (`$node`).

This analysis is the feature. Snap/insert are clients of it.

### 6. Closures vs imports (illegal crossings)

Nested in the scene file: `ground` (build) × `hLeft` (nested helper) — mentionable in the nested function via closure; not in `build()` until expose.

Imported helper: `ground` × private `hLeft` is illegal in **both** scopes until expose. Adding a parameter is the other fix and is **out**. v1: refuse the snap; expose is the way the parent names `hLeft`.

### 7. Single-value return vs expose

`return drill` makes `const bla = helper()` mention `bla`. Exposing a *different* local requires a bag and **breaks** callers that treat the return as a geom. v1 refuse with that reason. Do not silently wrap.

### 8. Length reuse on bag members

`hRight = parallelLine(right, hBottom.distance)` is a product field on a local. After expose, parent types `plate.hBottom.distance`. `fieldValue(scope, object, field)` today indexes `scope.circles[object]` by bind. Scope keys become mention strings or, better, lookup-by-Expr against id-keyed geom. `evalLengthExpr` must resolve nested members.

### 9. Focus must survive the write it causes

Expose rewrites `return mountingPlateLayout()` into `const plate = mountingPlateLayout()`, moving the call. Insert before `return` usually leaves earlier call sites stable, but not always. Rank-among-caller-frames from the **new** trace is the recovery; if the call vanished, drop to `build()`.

### 10. `tool.test.ts` mass

~1430 lines assume bind-keyed scope and `{ kind: "ref", name: "A" }`. Do not rewrite every fixture up front. Keep simple scenes working: one function, unique binds, `occ === 0` ⇒ mention `ref(bind)` as today. New tests cover two `plate()` calls, `plate.drill`, insert into the helper file, expose. Adapter: `scopeFromTrace(trace)` without a focus argument still means `build()` / first invocation / bind-as-ref when that is a legal mention.

## Necessary refactors (order)

Do these in order. Each unblocks the next. Do not grow `offset.ts`. Do not add a fourth insert job kind.

1. **Mention analysis** (return shape + caller bindings) keyed by **id**, tested on `mounting-plate.ts` + a fake parent. No UI yet.
2. **`Expr.member` generalization** + schema + `printExpr` / `exprRefs` / length parse. Existing `reach.radius` tests keep passing with the new shape.
3. **`scopeFromTrace(trace, focus)`** id-keyed, mention `Expr`, invocation filter. `boundOf` / pick / place / `exprOfPlace(p, scope)` / `sameRef` consume it. Bind-string `PlacePoint` goes away here — this is the invasive snap change.
4. **`insertCall` into an arbitrary function body** + `Insert.file` + function-local `takeBind` + member-aware `namesInFunctionScope`. Pane POSTs the focused file. Fillet patch unchanged aside from file.
5. **Pane focus / lock / mute / breadcrumb / expose.** Scope mute ≠ Fillet `mutePoints`. Escape / lock rules above.
6. **Pass scene:** `const plate = mountingPlateLayout()` in `apps/demo/src/scenes/mounting-plate.ts`. Expose and dive proven there.

## Not this prototype

- Paper, onion, palettes, applicator, join-by-id publication
- Auto-adding parameters so a helper can name the scene’s `ground`
- `group()`, instance transforms, “plate as a component”
- Nested destructure, spread, `return helper()`, typed return bags
- Insert into a loop body vs before the loop
- Switch-scope-and-restart when clicking muted geometry
- Using `evaluate().value` as the mentionable set
- Treating helper calls as groups or `occ` as a second document

## Honesty

The missing object is not a bag on `build()` and not a group around `plate()`. It is the same thing TypeScript already has: **which names are in scope at this function, and which evaluation of that function you are looking at.** Insert without that prints fiction. Snap without that proposes fiction. The refactors above are that object, not a feature on top of the current bind table.
