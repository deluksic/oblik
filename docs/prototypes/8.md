# Prototype 8 — mentionable scopes

**Status:** shipped (learned). The object is real: insert and snap print names legal in the focused **function + invocation**. Pass scene: `const plate = mountingPlateLayout()`. Remaining work is caller-side binding and collapsing nested live onto `n.inv` — not more mention features. Paper / publication stays paused (P7 horizon). P7 geometry is still the running tape.

UI copy: **refer**, not mention. **Add to return**, not expose. A private local is **not returned**. Analysis still says mention / return bag internally.

## Went well

**The three channels stayed unmixed.** Tape is id. Lexical names are the focused function’s JS environment. Helper return is what the caller may refer to (`plate.drill`, or `drill` after destructure). `Scope` has `prints` (snap) vs `liveKeys` (draw). Select is scope. Mute dims other invocations; drag and inspect stay global.

**`build` is not a special kind of scope.** The pane’s initial focus is the function `evaluate` invoked. Insert POSTs that file and function. The object-literal method `build() { … }` is one AST spelling next to `function plate()`.

**Edits in one helper body show on every invocation.** That is the shared source, not a component instance. Mute is how you tell *which* activation the names mean. Dive a plate, add a diagonal, Add to return, then refer to `plate.diag` from `build` — that was the product.

**Mention analysis is the clean new module.** Return shape, caller `const` / destructure / discarded, `onceIds`, insert-point names (params + direct `consts` + closures), loop-local exclusion. Join with the tape is id + `inv`, not `evaluate().value`.

**`Expr.member` is nested.** `plate.drill` and `plate.drill.radius` are `{ kind: "member", object: Expr, field: string }`. `exprRefs` is the root identifier. Do not stuff `plate.hBottom` into `{ kind: "ref", name: "plate.hBottom" }`.

**Invocation stamp is two-pass anchors**, after `build()` returns. Once-ids partition activations that share a caller key. Serial is not `occ`. We did not wrap user functions.

## Learned from using it

These showed up by diving plates, filleting a later occurrence, and adding `fillet()` to a helper — not from the charter.

**Draw and snap are different sets, and that is the product.** A focused invocation draws nested helper geometry at full strength (`liveKeys`, recursive). Snap stays mentionable-only (`prints`). Mixing them (mute follows snap, or snap follows draw) is wrong. Empty sidebar still peeks the full focused function.

**`occ === 0` is a silent default, not a helper identity.** `snapEligible` / `boundOf` without a filter still mean “first bind.” Region and fillet extra-picks forgot the scope keys and only the first plate’s corners/carriers were legal. Any new `hit()` that calls `snapRegion` / `snapLineCarrier` without `{ keys, print }` will regress the same way. Force the filter; do not treat missing keys as occ 0.

**Unknown callees are not helpers.** `fillet` and `along` are unmarked (`$site`-less), so mention `calls` records them as helper calls. Looking that name up and falling back to “some function in this file” treated `plate` as the callee and added **every** sibling invocation to `liveKeys`. Muting died the moment one fillet existed. Named miss must return nothing. `callsInFn` should not treat geom helpers as callees. Nested live should follow `n.inv`, not an AST call graph plus serial heuristics.

**Generated stacks collapse call sites.** Two `plate()` lines can share one generated caller line. `childNodes` then splits by `inv.serial`, or, if the focused function has only one call to that callee, takes **all** callee nodes — which is how a parent still draws, and how a nested helper under two plates can leak. Key callees by `{ file, name }`, not name alone.

**`isUserSourcePath` drops `/oblik/`.** Vitest stacks never look like user source. Scope/inv tests must stamp `n.module` / `n.at` / `n.stack` onto `apps/demo/src/…`. That is load-bearing, not sloppiness.

**Add to return is one-way.** It writes a shorthand field on the object-literal `return` (or `return { bind }` if there was none). After that, a caller that already bound the helper can refer to `plate.hLeft`. Removing a field is **not safe**: any parent that refers to it would fail the scene. Do not offer un-return. Do not wrap `return drill` into a bag (callers that used the geom directly would break). Caller-side binding when the call discarded the value (`const plate = helper()`) is still not wired — discarded calls stay unreferable until the user binds them.

**User-facing language.** Mention is the analysis word. The sidebar says refer / not returned / Add to return. Insert errors: `this scope cannot refer to X`.

## Why

Helpers already joined the tape. Inspect, drag, and fillet-by-id follow **id**, including into a helper. Insert and snap pretended the scene was one `build()` with unique `const` names: only `occ === 0` was named; `Expr.member` was a product field; insert always wrote the scene file.

The gap was **mentionability**: which names is it legal to print *here*, and which file/function is *here*. Reuse without that is a gallery of private geometry the parent cannot name.

## Locked (product)

**Scope is an editing object.** It is one **function** plus one **invocation** of that function: the insert destination, the referable set, and the live values those names currently hold. It is not a group, not a transform, not a paper join, not `evaluate().value`.

**`build` is not a special kind of scope.** Insert, snap, mute, mention analysis, and the sidebar treat it like any other. No `role: "build"` in the focus key.

**Three channels — do not mix**

| Channel | Role |
| --- | --- |
| Tape | See, drag, inspect, later ink. Helpers with ids join `current`. Join key is **id**. |
| Lexical names | Insert prints TypeScript. Refs must be in **that function’s JS environment**. |
| Helper return | What the **caller** may name (`plate.hBottom`, or `hBottom` after destructure). |

Scene `build()` returns like any other function. Insert writes before that return and does not wrap, strip, or special-case it. Add to return can put a scene local on `build()`'s object-literal bag the same way it does for a helper. Constructors still return values. Helpers may return a small struct — that is the construction API.

**Sidebar is the scope picker.** Selecting a node **is** scope selection (constructing function + the invocation that produced it). Scope selection is also possible **without** a node: the sidebar shows the current function and parent frames.

**Lock:** starting a constructing tool locks that scope for the verb. Escape clears the tool; locked-for-tool scope pops to the **parent** invocation (the caller). A muted click **refuses** (does not complete the verb, does not change scope).

**Mute:** not snap-eligible, still drawn weak. Drag, inspect, and jump-to-source stay **global (id)** — but a select click, because it is scope selection, will change scope when you are not in a locked tool. Fillet / literal / slider patch-by-id stay unscoped. **Do not ghost the in-progress construction on muted invocations.** Other evaluations of the same function stay dim drawings, not extra ghosts of the new segment.

**New `const`:** written in the focused function body, in that file. Preview prints **this scope’s** names (`hBottom` vs `plate.hBottom`).

**Add to return** writes a shorthand field on the helper’s object-literal `return`. Do not mint a second id. If the function does not return a bag, **do not wrap it**. **Do not remove a field from the return** — callers that refer to it would fail the scene.

**Out of this slice:** auto-adding helper parameters; `group()`; paper; nested destructure / spread / ternary returns; typed bags; treating `occ` as another component; switch-scope-and-restart on a muted click; ghosting a draft into sibling invocations; un-return.

## Pass / fail

Passed: mounting plate, parent binds the helper.

```ts
build() {
  const plate = mountingPlateLayout();
}
```

From that parent scope: snap `plate.drill`, not private `hLeft`. Add `hLeft` to the return → `plate.hLeft`. Dive (select a private, or pick the helper frame) → insert a segment in `layout/mounting-plate.ts` before that function’s `return`. Two `plate()` calls: cannot finish a **dived** line from invocation A to B. From the parent, `segment(a.c0, b.c0)` is legal — both are returned. The in-progress segment ghosts only on the focused plate.

Also exercised: `?scene=mounting-plate-grid` (3×2 loop of the same helper; serial = once-id `occ`); `?scene=nested-circles` (two-level helpers; parent draws nested geometry, cannot refer to the inner bead).

Fail would have been: insert still landing in the scene file when focus is the helper; printing `hLeft` from the parent; using `occ` as the helper-call identity; a `group()` around `plate()`; adding a `ground` parameter to the helper so a private can meet a scene line; special-casing `build` in insert/snap; extra ghosts on every invocation of the helper.

## Sidebar — selection is scope

**With a node selected.** Current scope = innermost user function whose body contains the constructor, and the invocation that produced this node. Clicking a **parent frame** retargets scope. Clicking the innermost frame is a no-op.

**With nothing selected.** The sidebar is the **current scope** with no geom identity. Opening a scene starts here: the entry function’s one invocation, no node. Child-invocation picking from the empty sidebar was locked and is not wired — dive by clicking geom.

**Handle drag and hover do not change scope.** Only select (click a geom with no locked tool) and explicit sidebar picks do.

**Escape:** if a tool is open, cancel the tool (and pop a tool-locked scope to its parent). If no tool and a node is selected, clear the node, **keep the scope**. If no tool and no node, pop scope to parent, or stay at the entry function.

That is the interaction between inspect and scope: they share the sidebar; they are not two trees.

## Invocation

### Purpose (only this)

Names printed in function F (`segment(A, B)`, `plate.drill`) mean the bindings of **one JS activation** of F. The invocation exists to exclude tape nodes whose live values are not what those names mean in that activation. Mixing two `plate()` calls and printing `segment(c0, c1)` would lie: each activation has its own `c0`.

Invocation is **not** the insert destination (source is shared). It is **not** a component instance. It is **not** `occ`.

Used for: snap eligibility, mute, live values in the ghost/preview, length numbers. Not used for: patch-by-id, handle drag, which file to write (the function is).

### What must be distinguished

| Situation | Example | Same function? | Same invocation? |
| --- | --- | --- | --- |
| Two call sites | `plate(); plate();` on two lines | yes | no |
| Same site, loop | `for (...) plate()` | yes | no (each iteration) |
| Different stacks | `build → plate` vs `build → fixture → plate` | yes | no |
| Recursion | `plate` on the stack twice | yes | no (inner vs outer) |
| Loop *inside* F | `for (...) circle(..., "o_ring")` | yes | **yes** (one call, many `occ` of that id) |
| Two helpers, same bind | both `const left` | no | — |

`occ` is per id. It collapses the first two rows with the ring loop: two `plate()` calls give `o_origin` occ 0,1; a ring loop inside one plate gives `o_ring` occ 0..n. You cannot use one integer for both jobs.

### Identity

An invocation of F is **one JS activation** (entry until return), including nested calls to *other* functions, excluding nested activations of **F itself**.

On the tape we do not have activation records. We have `stack: CallSite[]` (locations, not instances), `id`, `occ`, and order.

**Call-site key** = canonical caller frame of F (the user frame *outside* F’s source span). Distinguishes different sites (including `bolts(); bolts();` on one line — different columns), different stacks, and usually recursion (the recursive call is a different line). Does **not** distinguish `for (...) plate()`: every iteration has the same caller location, and sequential calls leave **no tape node in between**.

**Serial** = among activations that share `(F, caller key)`, the index in evaluation order (0, 1, …).

**Anchors (once-ids).** A constructor site in F whose AST parent is F and which is not inside a loop / `forEach` in F. If each activation constructs an anchor **exactly once**, that id’s `occ` *is* the serial. Looped ids inherit the serial of the activation they sit in. Second pass over the tape (not bump at `traced()`): for nodes of F with this caller key, anchors partition the sequence; nodes before the first anchor belong to serial 0; nodes between anchor `occ = k` and `occ = k+1` belong to `k+1`. Stamp `inv` after `build()` returns. Snap/mute read `n.inv`.

Native frames (`Array.forEach`) are already dropped. `points.forEach(hole)` has caller key = the `forEach` line in the parent. Serial at that site **is** the loop, and it splits iff `hole` has an anchor.

### When there is no anchor

The entry function is called once; `shared-loop`’s five rings are one invocation of `build` with five `occ` of `o_ring`. Extracting the loop body to `function hole(p) { circle(p, r, "o_h"); }` gives five calls, five `occ` of `o_h`, serial = that `occ`.

The remaining case is **the helper is itself a loop, and that helper is called from a loop (same call site)**:

```ts
function bolts() {
  for (let i = 0; i < 4; i++) circle(p(i), r, "o_bolt");
}
for (const g of groups) bolts();
```

Tape: eight `o_bolt` nodes, `occ` 0..7, **identical stacks**. Period 1, 4, or 8 is not knowable. Two `bolts(); bolts();` on *different lines* already differ in caller key.

**Fallback:** serial exists to keep **once-per-activation bindings** (`origin`, `drill`, `hBottom`) from meaning two live values at once. A function with no such binding has one scope per `(F, call site)`. Mash is the honest environment.

**Still a real lie (keep, do not wrap):** a **conditional** anchor (`if (flag) origin = point(...)`) merges a call that skips it with the next. Clustering by branded arguments is out of P8.

## Block scopes are not on the stack

`for` / `if` / `while` / bare `{ }` filter **referability** and they are **not** functions. `captureUserStack` never has a frame for them. P8’s scope object is `(function, invocation)` only.

Referable = names visible at the **insert point** (function tail), not every bind that function ever constructed. `const p` inside `for` is not snap-eligible while focus is `plate()`. Operationally that geometry is in this function invocation but **not snap-eligible** (same mute bucket as “not referable,” not “other invocation”).

We do not dive into non-function blocks. `let` / reassignment in a loop is out of mind: referable locals are `const` (plus params/closures).

## Mentionable set

Mentionable = names in the JS environment **at the insert point** (last statements of the focused function, before `return`), not every bind that function constructed.

| Provenance | Example | Snap prints | New `const` here? |
| --- | --- | --- | --- |
| Local (function body, not inside `for`/`if`) | `const hBottom = parallelLine(...)` | `hBottom` | yes, for new geometry |
| **Param** | `function plate(origin, gap)` | `origin` | **no** — already named |
| **Closure** | nested fn uses `ground` from the outer function | `ground` | **no** |
| Module import | `import { x } from …` | (ctors, not usually geom) | n/a |
| Caller field | `const plate = helper()` | `plate.drill` | no |

Block-local names (`const p` inside `for`) are **not** referable at the function tail.

**Params and closures are imports from an outer environment.** Same id as the caller’s geom (if it was branded); this scope’s print is the **local binding**, not the caller’s name. In `plate(A)`, dived into `plate`, snap should print `origin`; in the caller, the same id prints `A`. Analysis has the names; dived snap of a param is not wired yet.

They are not locals: snapping to them must not hoist `const origin = point(...)`. Auto-**adding** a parameter so a helper can name the parent’s `ground` stays **out**. Using **existing** params is in.

Plus, at the **caller**, fields of a helper result that this function bound:

| Caller writes | May refer |
| --- | --- |
| `const plate = mountingPlateLayout()` | `plate.origin`, `plate.drill`, … |
| `const { drill, origin } = mountingPlateLayout()` | `drill`, `origin` |
| `const { drill: d } = mountingPlateLayout()` | `d` |
| `mountingPlateLayout()` / `return mountingPlateLayout()` | nothing until Add to return **and** a caller binding (caller binding is not wired) |
| `const face = plate()` when `plate` does `return drill` | `face` as that one geom |

v1 analysis of the **return** (helper file):

- `return { origin, drill }` — shorthand field → that binding’s id.
- `return { extra: hBottom }` — field → `hBottom`’s id.
- `return { extra: parallelLine(..., "o_in") }` — field → trailing id of that call (no bind).
- `return drill` — whole-value; caller names the geom, not fields.

v1 **out:** spread, ternary, `return helper()`, deep destructure, `const x = plate; x.drill`, reassignment. Inline object returns must be **identifiers or constructor calls**, not clones (clones drop `$node`).

Shortest print wins when both exist (`hBottom` over `plate.hBottom`).

Product fields stay a **second** member step on a geom, not on the bag: `plate.drill.radius`, `hBottom.distance`.

Nested in the same file: outer names are closures (referable inside). An imported helper does not close over the caller’s names. Crossing caller `ground` × private `hLeft` is illegal in both scopes until Add to return.

## Non-bag return

`return drill` is a valid helper: the caller names the whole value. Adding a *different* local would wrap the return and **break** `const face = plate()`.

Do not silently wrap. Do not dump a stack error in the status line and leave the user to guess.

**UX:** Add to return is a sidebar action on a node that this function owns and that is **not returned**. If the function’s return is not an object literal (and not missing/`undefined`):

- The action is **visible but not a silent no-op**: it does not rewrite.
- Copy: this function returns a single value, so it has no return bag to add a field to.
- What would have to change: `return drill` → `return { drill, hBottom }`, and callers that used the geom directly (`const face = plate()`) must become `plate.drill`. We **do not** do that rewrite. No second wizard.

If there is **no** return, Add to return may add `return { hBottom }` — callers ignored the value; that is safe.

## Mute (compose, do not reuse)

Three mutes. They must not stomp each other.

| Channel | Who | Snap | Draw | Handles | Ghost |
| --- | --- | --- | --- | --- | --- |
| **Scope** | not this function, or other invocation of this function, or not referable here | ineligible | onion-weak | **stay** | **only focused invocation** |
| **Fillet chrome** | `muteStrokes` / `mutePoints` / `hideSnap` | hide snap | dim / hide points | **hide** (today) | fillet preview |
| **Region carriers** | `eligibleCarriers` | only those binds | dim the rest | stay | region ghost |

**Snap** is AND: a node must pass every active filter.

**Draw:** dim if *any* mute applies. Fillet may hide points; scope **never hides**, only dims. Do not reuse `mutePoints` for scope — that would hide handles and break “drag stays global.”

**Ghost:** one preview, on the focused invocation’s live values. Muted invocations of the same function do not get a copy of the in-progress segment. (They will grow that segment after insert + eval, as ordinary ink.)

**Inspect vs snap:** muted ink is still pickable for **select** (which sets scope). It is not snap-eligible while a constructing tool is locked.

Implementation: `mutedForScope(node)` beside Region’s `eligibleCarriers`, not a flag on `ToolChrome`. Pane/view compose the three.

## Add to return

Command on a selected node that this function constructed and that is **not returned**.

Rewrite, only if return is a bag or absent:

1. Helper or scene `build()`: add `{ bind }` to the object-literal `return`. If none, add `return { bind }`. **Shipped.**
2. Caller at this invocation’s call: if already `const plate = helper()` (or a destructure), stop after (1). If discarded, insert `const plate = helper()`. If destructure, add the name to the pattern. **Not shipped.**

One level only. Bubbling helper → fixture → entry function is Add to return twice.

**Do not remove a field from the return.** Nothing is using it is not a check we can trust from the helper file: any caller, including ones we have not opened, may refer to `plate.x`. Removing it crashes the scene. There is no un-return.

## Not this prototype

- Paper, onion, palettes, applicator, join-by-id publication
- Auto-adding parameters so a helper can name the caller’s `ground`
- Wrapping a single-value `return` into a bag
- **Removing a field from the return**
- `group()`, instance transforms, “plate as a component”
- Nested destructure, spread, `return helper()`, typed return bags
- Insert into a loop body vs before the loop
- Switch-scope-and-restart when clicking muted geometry
- Ghosting the draft into muted sibling invocations
- Wrapping user functions to push/pop activations (including Vite-only instrumentation)
- Clustering loop-only helpers by branded argument ids
- Using `evaluate().value` as the referable set
- Treating helper calls as groups or `occ` as a second document
- Modeling `for` as a scope
- Special-casing `build` in insert, snap, or focus types

## Honesty

The missing object was not a bag on `build()` and not a group around `plate()`. It is the same thing TypeScript already has: **which names are in scope at this function, and which evaluation of that function you are looking at.** Insert without that prints fiction. Snap without that proposes fiction. `build` is just the function we happened to enter first.

What remains is not “more mention features.” It is deleting the occ-0 default so a forgotten filter cannot quietly mean “first plate,” making insert as function-generic as the pane, and driving nested live keys from `inv` so `fillet()` cannot unmute siblings.
