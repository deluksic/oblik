# Prototype 8 — mentionable scopes

**Status:** design. Do not implement until the locked decisions below survive review. Paper / publication stays paused (P7 horizon). This prototype is the missing editing object: **the JS environment you are constructing into**, not a group and not a return bag for paper.

P7 stays the running geometry. This charter is the memory for what insert, snap, and helpers actually are, and which refactors they force.

## Why

Helpers already join the tape. `mountingPlateLayout()` is one constructor site per call, many `occ`, ids stamped in `src/layout/mounting-plate.ts`. Inspect, drag, and fillet-by-id already follow **id**, including into a helper.

Insert and snap do not. They still pretend the scene is one `build()` with unique `const` names:

- `insertCall` only finds `defineScene({ build() { … } })` and only accepts names from that body plus file imports (`namesInBuildScope`). A ref that exists only in a helper throws `geometry constructed in a helper cannot be inserted yet.`
- The pane always POSTs `file: props.file` (the scene), even when the live node’s `module` is the helper.
- `scopeFromTrace` / `boundOf` / `snapBoundPoint` key named geometry by **`n.bind` where `occ === 0`**. Two helpers that both `const left` shadow. Two `plate()` calls look like a loop: only occurrence 0 is mentionable.
- `Expr.member` is only `{ object: string; field: "radius" | "distance" }` — length reuse, not `plate.hBottom`.
- Place / crossings store **bind strings**, then `exprOfPlace` turns them into `{ kind: "ref", name: bind }`. That print is only legal when the focused function has that identifier.

The product gap is **mentionability**: which names is it legal to print *here*, and which file/function is *here*. Reuse without that is a gallery of private geometry the parent cannot name.

## Locked (product)

**Scope is an editing object.** It is one **function** plus one **invocation** of that function: the insert destination, the mentionable set, and the live values those names currently hold. It is not a group, not a transform, not a paper join, not `evaluate().value`.

**`build` is not a special kind of scope.** It is a function. Insert, snap, mute, mention analysis, and the sidebar treat it like any other. The pane’s *initial* scope is the function `evaluate` invoked (in our scenes that function is named `build`) because that is the call we control — not because the implementation has `if (isBuild)`. No `role: "build"` in the focus key. `findBuildBody` / `namesInBuildScope` become “find this function’s body / names.” The object-literal method `build() { … }` is one AST spelling of a function, next to `function plate()` and `const layout = () => {}`.

**Three channels — do not mix**

| Channel | Role |
| --- | --- |
| Tape | See, drag, inspect, later ink. Helpers with ids join `current`. Join key is **id**. |
| Lexical names | Insert prints TypeScript. Refs must be in **that function’s JS environment**. |
| Helper return | What the **caller** may name (`plate.hBottom`, or `hBottom` after destructure). |

Scene `build()` should return void for publication later; do not block this slice on deleting demo `return { A }`. Constructors still return values. Helpers may return a small struct — that is the construction API, not a scene export map.

**Sidebar is the scope picker.** The origin stack already is a stack of functions. Selecting a node **is** scope selection (that node’s constructing function + the invocation that produced it). Scope selection is also possible **without** a node: the sidebar shows the current function and lets you pick parent / child invocations. See [Sidebar](#sidebar--selection-is-scope).

**Lock:** starting a constructing tool on a mentionable point locks that scope for the verb. Escape clears the tool; locked-for-tool scope pops to the **parent** invocation (the caller), not to a magic `build` root. A muted click **refuses** (does not complete the verb, does not change scope).

**Mute:** not snap-eligible, still drawn weak. Drag, inspect, and jump-to-source stay **global (id)** — but a select click, because it is scope selection, will change scope when you are not in a locked tool. Fillet / literal / slider patch-by-id stay unscoped. **Do not ghost the in-progress construction on muted invocations** (P8). Other evaluations of the same function stay dim drawings, not extra ghosts of the new segment.

**New `const`:** written in the focused function body, in that file. Preview prints **this scope’s** names (`hBottom` vs `plate.hBottom`).

**Expose** does both sides: field on the helper `return { … }`, and a caller binding if the parent discarded the value. Do not mint a second id. If the function does not return a bag, **do not wrap it** — tell the user that function cannot export another name until they change the return (see [Non-bag return](#non-bag-return)).

**Out of this slice:** auto-adding helper parameters; `group()`; paper; nested destructure / spread / ternary returns; typed bags; treating `occ` as another component; switch-scope-and-restart on a muted click; ghosting a draft into sibling invocations.

## Pass / fail

Pass scene: mounting plate, parent binds the helper.

```ts
build() {
  const plate = mountingPlateLayout();
}
```

From that parent scope: snap `plate.drill`, not private `hLeft`. Expose `hBottom` → `plate.hBottom`. Dive (select a private, or pick the helper frame in the sidebar) → insert a segment in `layout/mounting-plate.ts` before that function’s `return`. Two `plate()` calls: cannot finish a **dived** line from invocation A to B. From the parent, `segment(a.c0, b.c0)` is legal — both are mentionable exports. The in-progress segment ghosts only on the focused plate, not on the muted one.

Fail: insert still landing in the scene file when focus is the helper; printing `hLeft` from the parent; using `occ` as the helper-call identity; a `group()` around `plate()`; adding a `ground` parameter to the helper so a private can meet a scene line; special-casing `build` in insert/snap; extra ghosts on every invocation of the helper.

## Sidebar — selection is scope

Today the sidebar is **Identity** (bind / id) plus **Origin** (the node’s user stack, one quoted frame per function). That stack is already the interesting scopes: the constructor’s function, then who called it, then who called that.

**With a node selected.** Current scope = innermost user function whose body contains the constructor, and the invocation that produced this node. The stack is that node’s stack. Clicking a **parent frame** retargets scope to that function + invocation (the node can remain selected as the reason you have this stack). Clicking the innermost frame is a no-op. This is dive / surface without a second widget.

**With nothing selected.** The sidebar is not an empty “hover or click geometry.” It is the **current scope** with no geom identity: function header, file, invocation among siblings if that is more than one. From here you can pick a **child** invocation (a helper this call ran — list them from the tape) or the **parent** (the caller). Opening a scene starts here: the entry function’s one invocation, no node.

**Handle drag and hover do not change scope.** Only select (click a geom with no locked tool) and explicit sidebar picks do.

**Escape:** if a tool is open, cancel the tool (and pop a tool-locked scope to its parent). If no tool and a node is selected, clear the node, **keep the scope**. If no tool and no node, pop scope to parent, or stay at the entry function.

That is the interaction between inspect and scope: they share the sidebar; they are not two trees.

## Invocation

### Purpose (only this)

Names printed in function F (`segment(A, B)`, `plate.drill`) mean the bindings of **one JS activation** of F. The invocation exists to exclude tape nodes whose live values are not what those names mean in that activation. Mixing two `plate()` calls and printing `segment(c0, c1)` would lie: each activation has its own `c0`.

Invocation is **not** the insert destination (source is shared). It is **not** a component instance. It is **not** `occ`.

Used for: snap eligibility, mute, live values in the ghost/preview, length numbers. Not used for: patch-by-id, handle drag, which file to write (the function is).

### What must be distinguished

| Situation | Example | Same function? | Same invocation? |
| --- | --- | --- | --- |
| Two call sites | `plate(); plate();` on two lines | yes | no |
| Same site, loop | `for (...) plate()` | yes | no (each iteration) |
| Different stacks | `build → plate` vs `build → fixture → plate` | yes | no |
| Recursion | `plate` on the stack twice | yes | no (inner vs outer) |
| Loop *inside* F | `for (...) circle(..., "o_ring")` | yes | **yes** (one call, many `occ` of that id) |
| Two helpers, same bind | both `const left` | no | — |

`occ` is per id. It collapses the first two rows with the ring loop: two `plate()` calls give `o_origin` occ 0,1; a ring loop inside one plate gives `o_ring` occ 0..n. You cannot use one integer for both jobs.

### Identity

An invocation of F is **one JS activation** (entry until return), including nested calls to *other* functions, excluding nested activations of **F itself**.

On the tape we do not have activation records. We have `stack: CallSite[]` (locations, not instances), `id`, `occ`, and order.

**Call-site key** = canonical caller frame of F (the user frame *outside* F’s source span). Distinguishes different sites (including `bolts(); bolts();` on one line — different columns), different stacks, and usually recursion (the recursive call is a different line). Does **not** distinguish `for (...) plate()`: every iteration has the same caller location, and sequential calls leave **no tape node in between** — the last constructor of call 1 and the first of call 2 have identical stacks.

**Serial** = among activations that share `(F, caller key)`, the index in evaluation order (0, 1, …).

**Anchors (once-ids).** A constructor site in F whose AST parent is F and which is not inside a loop / `forEach` in F. If each activation constructs an anchor **exactly once**, that id’s `occ` *is* the serial. Looped ids inherit the serial of the activation they sit in. Do this in a **second pass** over the tape (not by bumping at `traced()` in order): for nodes of F with this caller key, anchors partition the sequence; nodes before the first anchor belong to serial 0; nodes between anchor `occ = k` and `occ = k+1` belong to `k+1`. That way the anchor may sit *after* a loop in the body (`for (...) circle; const origin = point(...)` still splits two `plate()` calls). Online bump at the moment the anchor fires would mis-tag the second call’s loop as serial 0.

Stamp `inv` on `TraceNode` after `build()` returns (same eval, same stack coordinates). Snap/mute read `n.inv`. Do not use `pinConstructorSite` (it overwrites frame 0 with annotation lines).

Native frames (`Array.forEach`) are already dropped. `points.forEach(hole)` has caller key = the `forEach` line in the parent. Serial at that site **is** the loop, and it splits iff `hole` has an anchor.

### When there is no anchor

This is **not** “a loop in `build()`.” The entry function is called once; `shared-loop`’s five rings are one invocation of `build` with five `occ` of `o_ring`. That is the desired object.

Extracting the loop *body* also does not hit this:

```ts
function hole(p) {
  circle(p, r, "o_h"); // anchor of hole — once per call
}
for (const p of pts) hole(p);
```

Five calls, five `occ` of `o_h`, same caller key, serial = that `occ`. Works.

The remaining case is **the helper is itself a loop, and that helper is called from a loop (same call site)**:

```ts
function bolts() {
  for (let i = 0; i < 4; i++) circle(p(i), r, "o_bolt");
}
for (const g of groups) bolts(); // or pts.forEach(bolts)
```

Tape: eight `o_bolt` nodes, `occ` 0..7, **identical stacks**. Period 1, 4, or 8 is not knowable (the `4` may be a slider). Two `bolts(); bolts();` on *different lines* already differ in caller key — no anchor needed.

`mountingPlateLayout` does not look like this: it starts with `origin = point(...)`. Two plates plus an inner hole loop still split on `o_origin`. The realistic hit is `boltRing` / `ticks` / `grid` — the loop *is* the helper — reused from a `for`.

**What mash-to-one-invocation actually does.** Insert still writes the shared body (correct). You cannot mention “the third call” in that body anyway: there is no `const origin` that differs per call, only looped `o_bolt` (same as rings in `shared-loop`: named snap is `occ === 0`, drag-any, draft-all). Splitting serials would not add a legal *print*; it would only mute other clusters and aim the ghost at one cluster. P8 already refuses sibling ghosts. Mute-isolation of call 3 is the only leftover, and it is cosmetic next to name honesty.

**Params look like an exception and mostly are not.** `function bolts(center) { for (...) circle(center, r, "o_b"); }` has a per-activation name `center` with no constructor in F. Inserting `circle(center, r)` still runs every call with that call’s argument — mashed or split. Snapping two different passed points as two refs inside `bolts` would print `segment(center, center)`. Mash is the honest environment. Split would only dim the other groups’ ink.

**So the fallback is a principle, not a hole:** serial exists to keep **once-per-activation bindings** (`origin`, `drill`, `hBottom`) from meaning two live values at once. A function with no such binding has one scope per `(F, call site)`. That is the same object as “the loop body” in `shared-loop`.

**Still a real lie (keep, do not wrap):** the anchor is **conditional** (`if (flag) origin = point(...)`). A call that skips it merges with the next. Clustering by branded arguments (`for (const p of pts) bolts(p)` → group child nodes by imported id) would split some loop-only helpers without wrapping; skip it in P8 (easy to get wrong with closures). Transform-only `enter`/`leave` around every user function would be complete and would not touch disk; also out of P8.

**`emit` / nested `evaluate`:** copied nodes keep their original `inv`. **Async:** `build` is sync.

### Block scopes are not on the stack

`for` / `if` / `while` / bare `{ }` filter **mentionability** and they are **not** functions. `captureUserStack` never has a frame for them. P8’s scope object is `(function, invocation)` only.

```ts
function plate() {
  const origin = point(0, 0, "o_origin");
  for (let i = 0; i < 4; i++) {
    const p = point(px(i), py(i), "o_p");
    circle(p, 0.1, "o_hole");
  }
}
```

`p` is in scope only inside the `for` body. Insert-before-`return` is *after* the loop: `segment(p, origin)` is illegal TypeScript. Selecting a hole still dives to `plate()` (the innermost *function*), not the loop — there is no loop frame in the sidebar stack.

**Correctness without modeling `for` as a scope:** mentionable = names visible at the **insert point** (function tail), not every bind that function ever constructed. `p` / `i` / `o_p` are not snap-eligible while focus is `plate()`. `origin` is. That match is what `namesInBuildScope` already does (direct body statements only); `scopeFromTrace` does **not** (it will offer `p` at `occ === 0`). P8 must use the insert-point set for snap, not the tape-bind set.

**P8 lock:** we do not dive into non-function blocks, and we do not mention names that only exist there. That is **enough for correctness** if “mention” includes snap, crossings, gliders, length reuse, and preview — not only the insert validator. Inspect/drag stay on id; they do not print those names.

Operationally: mentionable = names visible at the insert point; loop-local geometry is in this function invocation but **not snap-eligible** (same mute bucket as “not mentionable,” not “other invocation”). `scopeFromTrace` offering `p` at `occ === 0` is a bug against this lock, not a second problem.

**Not covered by that slogan (still true, still out or separate):**

- Function-level `let p` assigned inside the loop — the name *is* visible at the tail and means the **last** iteration. Clicking occ 0 and printing `p` lies. P8: only treat `const` at the function body (and params/closures) as locals; do not walk assignments.
- Conditional anchors merging two *function* calls (example 7).
- Actually inserting into the loop/`if` body.

Callbacks **are** functions (`pts.forEach((p) => { … })`, nested `function`). They get a stack frame and a P8 scope. `for` does not. Do not conflate them.

### HMR

A new eval produces a new tape. Identity must be **re-derived**, not a stale `{ line, column }`.

- **Function key:** `{ file, name }` (arrows: file + nearest `const name =`). Re-resolve the span from the current AST. Spans move; names usually do not.
- **If a node is selected:** current scope is that node’s function + `inv` recomputed on the new node with the same **id**. If `occ` shifted (they inserted a `plate()` before this one), following **id + occ** is wrong; following **id** and nearest `inv` serial is also wrong. **Selected node after HMR:** match `id` and, if several, keep `occ` if that occ still exists, else drop the node and keep `{ fn, caller key, serial }` if that serial still exists, else the function’s last invocation, else the parent. Prefer this over persisting line numbers.
- **If no node is selected:** persist `{ fn, caller key, serial }`. Recompute serials from the new tape the same way (deterministic). If that serial no longer exists, clamp to the last invocation of that caller key; if the call site vanished, parent function, then entry function.
- **Do not** keep generated-position stacks across HMR. Re-read `n.stack` / `n.inv` from the new trace.

The selected node is the robust anchor. That is another reason selection and scope share the sidebar.

## Mentionable set

Mentionable = names in the JS environment **at the insert point** (P8: last statements of the focused function, before `return`), not every bind that function constructed.

| Provenance | Example | Snap prints | New `const` here? |
| --- | --- | --- | --- |
| Local (function body, not inside `for`/`if`) | `const hBottom = parallelLine(...)` | `hBottom` | yes, for new geometry |
| **Param** | `function plate(origin, gap)` | `origin` | **no** — already named |
| **Closure** | nested fn uses `ground` from the outer function | `ground` | **no** |
| Module import | `import { x } from …` | (ctors, not usually geom) | n/a |
| Caller field | `const plate = helper()` | `plate.drill` | no |

Block-local names (`const p` inside `for`) are **not** mentionable at the function tail. See [Block scopes](#block-scopes-are-not-on-the-stack).

**Params and closures are imports from an outer environment.** Same id as the caller’s geom (if it was branded); this scope’s mention is the **local binding**, not the caller’s name. In `plate(A)`, dived into `plate`, snap prints `origin`; in the caller, the same id prints `A`. The scope chooses the print.

They are not locals: snapping to them must not hoist `const origin = point(...)`. They are not module imports: the binding is per invocation (the argument *value* changes). Analysis and snap lookup should keep the provenance so insert/preview can refuse to re-bind them.

Auto-**adding** a parameter so a helper can name the parent’s `ground` stays **out**. Using **existing** params is in.

Plus, at the **caller**, fields of a helper result that this function bound:

| Caller writes | Mentions |
| --- | --- |
| `const plate = mountingPlateLayout()` | `plate.origin`, `plate.drill`, … |
| `const { drill, origin } = mountingPlateLayout()` | `drill`, `origin` |
| `const { drill: d } = mountingPlateLayout()` | `d` |
| `mountingPlateLayout()` / `return mountingPlateLayout()` | nothing until expose inserts a binding |
| `const face = plate()` when `plate` does `return drill` | `face` as that one geom |

v1 analysis of the **return** (helper file):

- `return { origin, drill }` — shorthand field → that binding’s id.
- `return { extra: hBottom }` — field → `hBottom`’s id.
- `return { extra: parallelLine(..., "o_in") }` — field → trailing id of that call (no bind).
- `return drill` — whole-value; caller names the geom, not fields.

v1 **out:** spread, ternary, `return helper()`, deep destructure, `const x = plate; x.drill`, reassignment. Inline object returns must be **identifiers or constructor calls**, not clones (clones drop `$node`).

Shortest mention wins when both exist (`hBottom` over `plate.hBottom`).

Product fields stay a **second** member step on a geom, not on the bag: `plate.drill.radius`, `hBottom.distance`. That is length reuse, already in the prompt as `reach.radius`.

Nested in the same file: outer names are closures (mentionable inside). An imported helper does not close over the caller’s names. Crossing caller `ground` × private `hLeft` is illegal in both scopes until expose.

## Non-bag return

`return drill` is a valid helper: the caller names the whole value. Expose of a *different* local would wrap the return and **break** `const face = plate()`.

Do not silently wrap. Do not dump a stack error in the status line and leave the user to guess.

**UX (locked):** Expose is a sidebar action on a node that this function owns but does not export. If the function’s return is not an object literal (and not missing/`undefined`):

- The action is **visible but not a silent no-op**: it does not rewrite.
- Copy states the constraint in the sidebar, next to the return line we already quote: this function returns a single value, so it has no bag to add a field to.
- What would have to change: `return drill` → `return { drill, hBottom }`, and callers that used the geom directly (`const face = plate()`) must become `plate.drill` (or a destructure). We **do not** do that rewrite in P8. Showing the existing return line (origin already does) plus that sentence is the whole UI. No second wizard.

If there is **no** return, expose may add `return { hBottom }` — callers ignored the value; that is safe.

## Mute (compose, do not reuse)

Three mutes already exist or will. They must not stomp each other.

| Channel | Who | Snap | Draw | Handles | Ghost |
| --- | --- | --- | --- | --- | --- |
| **Scope** | not this function, or other invocation of this function, or not mentionable here | ineligible | onion-weak | **stay** | **only focused invocation** (P8: no sibling ghosts) |
| **Fillet chrome** | `muteStrokes` / `mutePoints` / `hideSnap` | hide snap | dim / hide points | **hide** (today) | fillet preview |
| **Profile carriers** | `eligibleCarriers` | only those binds | dim the rest | stay | profile ghost |

**Snap** is AND: a node must pass every active filter. A fillet session in a dived helper snaps only mentionable + this invocation + fillet’s own rule.

**Draw:** dim if *any* mute applies. Fillet may hide points; scope **never hides**, only dims. Do not reuse `mutePoints` for scope — that would hide handles and break “drag stays global.”

**Handles:** visible if grabbable and the *tool* did not hide them. Scope mute does not hide handles. Drag does not require snap eligibility and does not change scope.

**Ghost:** one preview, on the focused invocation’s live values. Muted invocations of the same function do not get a copy of the in-progress segment. (They will grow that segment after insert + eval, as ordinary ink.)

**Inspect vs snap:** muted ink is still pickable for **select** (which sets scope). It is not snap-eligible while a constructing tool is locked. Hover can still highlight muted geometry.

Implementation: `mutedForScope(node)` beside Profile’s `eligibleCarriers`, not a flag on `ToolChrome`. Pane/view compose the three.

## Expose

Command on a selected node that this function constructed and that the **parent** scope cannot mention. (Select already put you in this function; the parent is the next frame.)

Rewrite, only if return is a bag or absent:

1. Helper: add `{ bind }` to the object-literal `return`. If none, add `return { bind }`.
2. Caller at this invocation’s call: if already `const plate = helper()` (or a destructure), stop after (1). If discarded, insert `const plate = helper()`. If destructure, add the name to the pattern.

One level only. Bubbling helper → fixture → entry function is expose twice.

## Hard problems

These are the reasons not to “just pass a file into `insertCall`.”

### 1. Stack coordinates are not source coordinates

`captureUserStack` records **generated** positions. Inspect remaps later via `/__map-stack`. Tools today never look at `stack` for snap.

Stamp `inv` at `traced()` from that eval’s stacks (same coordinates as every other node). Canonicalize paths (`normalizeStackFile` / a real join, not `normalizeSceneRelPath` which only rewrites using the *constructor* module — helper vs scene frames already disagree in `stackForNode` tests). Snap reads `n.inv`. See [Invocation](#invocation).

### 2. Tape bind is not unique and `occ === 0` is the wrong filter

`scopeFromTrace` is already wrong for two `const left` in two functions. Place crossings, `PlaceHit.carrier.bind`, `hoverBind`, Profile `n.bind && n.occ === 0`, length hover, `eligibleCarriers` — all of it.

**Resolution:** snap and scope key by **id** + `inv`. `PlacePoint` / crossings store ids, not binds. `exprOfPlace(p, scope)` asks the focused scope for the mentionable `Expr`. Params/closures resolve to that Expr (`ref("origin")`), not a new constructor.

Do not stuff `plate.hBottom` into `{ kind: "ref", name: "plate.hBottom" }`. `exprRefs` would treat that as one identifier. That forces problem 3.

### 3. `Expr.member` cannot express helper fields

Today `{ kind: "member"; object: string; field: ProductField }`. Need `plate.hBottom` and `plate.drill.radius`.

```ts
{ kind: "member"; object: Expr; field: string }
```

Product vs bag is a lookup. Schema, `exprRefs` (root identifiers only), `printExpr`, `sameRef` (compare Expr), `memberExpr` in `length.ts` change together.

### 4. Insert destination is hard-wired to `build()` in the scene file

That is a special case of `build`. Kill it. Destination = focused function’s body, that file, before **its** `return`. `used` / `takeBind` from **that function** plus file-level imports. Two functions in one file may both `const s`. `ensureNamedImport` stays file-level. Fillet patch stays unscoped (by id).

`namesInFunctionScope(source, fn)`: module imports + **params** + closures from outer same-file functions + this body’s locals. Semantic check for member chains.

### 5. Mention graph is new analysis

`bindName` only sees `const ident = ctor(...)`. Need return shape, caller bindings, and **param / closure provenance**. Join with the tape by id + `inv`. Do not read `evaluate().value`.

### 6. No anchor ⇒ one invocation per call site

See [When there is no anchor](#when-there-is-no-anchor). Not a wrap-or-bust bug: without once-per-activation names, extra serials do not unlock mentions. Conditional anchors can still merge two calls; accept that in P8.

### 7. Length reuse on bag members

`evalLengthExpr` must resolve nested members (`plate.hBottom.distance`).

### 8. Focus after the write it causes

Expose rewriting `return mountingPlateLayout()` moves the call. Re-derive from the selected node if any; else `{ fn, caller key, serial }` on the new tape. If the call vanished, parent function.

### 9. `tool.test.ts` mass

~1430 lines assume bind-keyed scope. Keep simple scenes: one function, unique binds, `occ === 0` ⇒ mention `ref(bind)`. Default focus in tests is the entry function (whatever `evaluate` called), not a `build`-only helper. New tests: two `plate()` calls, loop of `plate()`, `plate.drill`, param mention, insert into the helper file, expose, mute+fillet compose, no sibling ghosts.

## Necessary refactors (order)

Do these in order. Each unblocks the next. Do not grow `offset.ts`. Do not add a fourth insert job kind.

1. **Mention analysis** (return shape + caller bindings + params/closures) keyed by **id**. Tests on `mounting-plate.ts` + a fake parent. No UI yet.
2. **`Expr.member` generalization** + schema + `printExpr` / `exprRefs` / length parse. Existing `reach.radius` tests keep passing with the new shape.
3. **Stamp `inv` on `TraceNode` (two-pass anchors)** + `scopeFromTrace(trace, focus)` id-keyed, mention `Expr`, invocation filter. Pick/place/`exprOfPlace(p, scope)` consume it. No wrap of user functions.
4. **`insertCall` into an arbitrary function body** + `Insert.file` + function-local `takeBind` + `namesInFunctionScope`. No `findBuildBody` special case. Pane POSTs the focused file.
5. **Pane + sidebar:** current scope, select = scope, empty sidebar = current scope, mute compose, lock, expose copy for non-bag returns. No sibling ghosts.
6. **Pass scene:** `const plate = mountingPlateLayout()` in `apps/demo/src/scenes/mounting-plate.ts`.

## Honesty

The missing object is not a bag on `build()` and not a group around `plate()`. It is the same thing TypeScript already has: **which names are in scope at this function, and which evaluation of that function you are looking at.** Insert without that prints fiction. Snap without that proposes fiction. `build` is just the function we happened to enter first.
